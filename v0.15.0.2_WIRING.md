## 🔍 Architecture Pattern

**ChainManager delegates to BlockAcceptor (does NOT replace it)**:

```
Block Arrival
    ↓
BlockAcceptor::AcceptBlockFromRPC()
    ├─ Validate block
    ├─ ConnectBlock (UTXO updates, undo record creation)
    ├─ NotifyBlockConnected
    └─ ActivateBestChain() ← NEW
           ↓
ChainManager::ActivateBestChain()
    ├─ GetBestCandidate() (compares chainwork)
    ├─ FindFork()
    └─ PerformReorg()
           ├─ DisconnectBlock() → calls BlockAcceptor::DisconnectBlock()
           └─ ConnectBlock() → calls BlockAcceptor::ConnectBlock()
```

**Key Design Principles**:
- ✅ BlockAcceptor remains single write authority (ChainWriteToken)
- ✅ ChainManager only coordinates, never executes directly
- ✅ Undo logic (v0.15.0.1) unchanged
- ✅ Safe early return if BlockIndex tree not populated

## ⚠️ Current Limitations (Expected for v0.15.0.2)

### BlockIndex Tree Not Populated

**Status**: ActivateBestChain() returns early with "No candidates available"

**Why**: BlockAcceptor doesn't create `CBlockIndex` entries during block acceptance yet.

**Effect**:
- ✅ Manual reorgs work (via `invalidateblock` RPC)
- ✅ System doesn't crash (safe early return)
- ⏸️ Automatic fork selection not triggered (requires BlockIndex entries)

**Next Step (v0.15.0.3+)**: Add BlockIndex creation to BlockAcceptor::ConnectBlock()
