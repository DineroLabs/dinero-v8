# Releasing Dinero v8.0.0 — Operator Runbook

This document covers **Phases 3–6 of the v8 consolidation plan** —
release pipeline migration, repo rename + archival, fleet cutover, and
the v8.0.0 tag cut. Source-side Phase 1 (subtree merge) and Phase 2
(CMake modularization + firewall + version unification) are already on
the `consolidate` branch of `DineroLabs/Dinero-Coin` along with the
full v8 peer-discovery work (Phases A–E) and the GPU backend stack.

Phases 3–6 are **operator-in-loop** by design: they touch credentials
(codesigning, Apple notarization, Authenticode), public state (GitHub
repo rename, archived repos, the v8.0.0 tag), and production daemons
(LA / VA / MO / CN). This runbook documents the exact sequence and
rollback procedure for each phase so the steps are repeatable.

The `consolidate` branch at the time this runbook landed is the source
of truth. After Phase 4 merges it into `dinero-main`, record the exact
merge commit as `RELEASE_COMMIT` and use that commit for Phase 3
artifacts, Phase 5 fleet canaries, and the Phase 6 `v8.0.0-rc1` tag.
The first `git push origin v8.0.0-rc1` is the irreversible public
commitment for this release candidate.

## Phase 3 — Release pipeline (operator drives signing, I drove the script edits)

The signing/notarization/installer/packaging scripts have already been
adjusted for monorepo paths in this branch. Phase 3 is operator-side
first-execution: actually running them with credentials to produce the
v8.0.0-rc1 artifacts.

### 3.A macOS — staging script + Developer ID signing + Apple notarization

Operator runs from the consolidate worktree on the signing Mac (the one
with `Developer ID Application: Mirsad Hajdarevic (JXJS6ZA5FJ)` in
keychain + `notarization-profile` configured). The staging is now
scripted symmetrically with Windows + Linux.

```bash
# 1. Build the monorepo stack (already done by pre-flight check).

# 2. Stage the .app + standalone binaries + produce the unsigned DMG/zip.
#    Same -Version flag shape as the Windows / Linux scripts.
./packaging/mac/build-installer.sh --version 8.0.0-rc1

# 3. Developer ID-sign the .app inside packaging/mac/dist/stage/.
#    --options runtime is required for notarization (hardened runtime).
APP=packaging/mac/dist/stage/dinero-qt.app
codesign --force --deep --options runtime --timestamp \
         --entitlements qt/packaging/entitlements.plist \
         --sign "Developer ID Application: Mirsad Hajdarevic (JXJS6ZA5FJ)" \
         "$APP"
codesign --verify --deep --strict --verbose=2 "$APP"
spctl --assess --type execute --verbose=2 "$APP"   # should report "accepted"

# 4. Notarize the .zip (Apple's notarytool takes .zip or .dmg).
ZIP=packaging/mac/dist/Dinero-v8.0.0-rc1-macOS-arm64-qt.zip
xcrun notarytool submit "$ZIP" --keychain-profile notarization-profile --wait

# 5. Staple ticket onto the .app so it verifies offline.
xcrun stapler staple "$APP"
xcrun stapler validate "$APP"

# 6. Re-create the DMG from the now-stapled .app, sign, notarize, staple.
DMG=packaging/mac/dist/Dinero-v8.0.0-rc1-macOS-arm64.dmg
rm -f "$DMG"
hdiutil create -volname "Dinero v8.0.0-rc1" \
               -srcfolder packaging/mac/dist/stage \
               -ov -format UDZO "$DMG"
codesign --sign "Developer ID Application: Mirsad Hajdarevic (JXJS6ZA5FJ)" \
         --timestamp "$DMG"
xcrun notarytool submit "$DMG" --keychain-profile notarization-profile --wait
xcrun stapler staple "$DMG"
xcrun stapler validate "$DMG"
```

**Verification:** download to a fresh Mac (no developer tools, no
prior install), run the DMG, expect zero Gatekeeper warnings. If
Gatekeeper objects, stapling failed — re-run step 5/6.

### 3.B Windows — Authenticode + NSIS installer

Operator runs on the Windows MSVC build host (the one that produced
v2.2.6-rc5 successfully) from a Developer Command Prompt for VS 2022:

```powershell
# 1. Build the monorepo stack (canonical command for v8 release).
cmake -S . -B build-msvc-native -G "Visual Studio 17 2022" -A x64 `
      -DCMAKE_BUILD_TYPE=Release `
      -DDINERO_BUILD_QT=ON -DDINERO_BUILD_MINER=ON `
      -DMINER_ENABLE_CUDA=ON -DMINER_ENABLE_OPENCL=ON `
      -DENABLE_GPU_MINING=ON `
      -DENABLE_GRPC=OFF -DENABLE_HARDWARE_WALLETS=OFF `
      -DCMAKE_PREFIX_PATH="C:\Qt\6.9.1\msvc2022_64"
cmake --build build-msvc-native --config Release `
      --target dinerod dinero-cli dinero-solo-miner-cli dinero-qt `
                dinero-miner dinero-gpu-miner dinero-stratum-worker

# 2. Authenticode-sign every binary (operator has the .p12 cert).
$signtool = 'C:\Program Files (x86)\Windows Kits\10\bin\10.0.22621.0\x64\signtool.exe'
$cert     = 'C:\path\to\dinero-codesign.p12'
$pw       = $env:CERT_PASSWORD   # supplied per-session; never committed

$binaries = 'dinerod','dinero-cli','dinero-qt','dinero-solo-miner',
            'dinero-miner','dinero-gpu-miner','dinero-stratum-worker'
foreach ($b in $binaries) {
    & $signtool sign /f $cert /p $pw `
        /t http://timestamp.digicert.com `
        /fd SHA256 `
        "build-msvc-native\Release\$b.exe"
}

# 3. Run the v8-aware installer builder. Defaults now point at the
#    in-tree qt/ subdir (no more ..\dinero-qt sibling-repo path).
.\packaging\windows\build-installer.ps1 -Version 8.0.0-rc1

# 4. Sign the installer.
& $signtool sign /f $cert /p $pw `
    /t http://timestamp.digicert.com `
    /fd SHA256 `
    .\packaging\windows\dist\Dinero-8.0.0-rc1-windows-x86_64-Setup.exe
```

**Verification:** download to a fresh Windows 11 VM, run the installer,
expect zero SmartScreen warnings (or only "this app is new" warnings
that go away after a few hundred downloads — Authenticode reputation
takes time).

Operator SSHes into the Ubuntu 24.04 Dell builder. The staging is now

```bash
# Verify the .deb installs cleanly in a chroot or sandbox.
sudo dpkg -i packaging/linux/dist/dinero-core_8.0.0~rc1-1_amd64.deb
sudo systemctl status dinerod   # should be "loaded (inactive)" — opt-in start
sudo systemctl start dinerod
sudo journalctl -u dinerod -f
```

**Verification:** `sudo systemctl start dinerod` brings the daemon up
on the Dell, it connects to peers within ~30s, height advances toward
mainnet tip.

## Phase 4 — Repository cutover

The source side is on `DineroLabs/Dinero-Coin/consolidate`. Phase 4
elevates the monorepo to the canonical location and archives the old
satellite repos.

**Sequence — order matters:**

```
4.1  On DineroLabs/Dinero-Coin: merge `consolidate` into `dinero-main`
     via PR. Once this merge lands, dinero-main IS the monorepo.

4.2  GitHub Settings → rename DineroLabs/Dinero-Coin → DineroLabs/dinero.
     GitHub 301-redirects the old URL for the foreseeable future
     (precedent: Trucker2827 → DineroLabs transfer Apr 2026 still
     redirects).

4.3  Update every local clone's origin remote:
       git remote set-url origin git@github.com:DineroLabs/dinero.git
     (yours, plus any operator clones, plus fleet nodes — see Phase 5.)

4.4  Archive DineroLabs/dinero-qt as read-only via Settings → Archive.
     Pin a README banner: "This repo is read-only; development
     continues at github.com/DineroLabs/dinero. Tags like v2.2.6-rcN
     remain valid for archaeology."

4.5  Archive DineroLabs/dinero-solo-miner identically.

4.6  Update DineroLabs/dinero-releases README to point at the new
     monorepo source.
```

**What does NOT change in Phase 4:**

- `dinero-sv2`, `wdin-bridge`, iOS DineroDPI — all stay separate repos
- Existing tags on dinero-qt / dinero-solo-miner — they stay where they
  are; v2.2.6-rc5 on dinero-qt remains the canonical source for that
  Windows installer
- `dinero-miner` (Windows CPU miner sibling) — pre-v8.0.0 release
  blocker decision pending; current plan is to leave it as an external
  optional dependency for v8.0.0 and revisit before v8.0.0 final

**Tag semantics:** old tags on the archived repos stay where they are
for binary provenance. New monorepo tags start at `v8.0.0-rc1`. A
`docs/release-history.md` file in the monorepo cross-references the
old tags to the archived repo URLs.

## Phase 5 — Fleet deploy path cutover

All four fleet nodes (LA, VA, MO, CN) currently run dinerod from
`/root/Dinero-Coin/build/dinerod`. After Phase 4's GitHub rename, the
canonical clone path is `/root/dinero/build/dinerod`. Phase 5 migrates
each node.

**Critical safety rules:**
- Use `systemctl stop dinerod` (SIGTERM) — never `kill -9` (per memory:
  hard-kill corrupts ChainDB SST files)
- Touch ONLY the binary path and systemd unit. Datadir stays untouched.
- One node at a time. Verify each before moving to the next.
- Do not require the public `v8.0.0-rc1` tag yet. Fleet canaries pin
  the exact post-merge `RELEASE_COMMIT`; Phase 6 tags that same commit
  after the fleet has run cleanly for the watch window.

Before touching the first node, record the release commit from the
renamed monorepo:

```bash
cd /Users/haydarevich/src/_rc/consolidate
git fetch origin
git rev-parse origin/dinero-main   # save this as RELEASE_COMMIT
```

**Per-node procedure:**

```bash
ssh root@<node>   # node = MO, then CN, then VA, then LA

# 1. Stop the daemon cleanly.
systemctl stop dinerod.service
sleep 5
pgrep dinerod   # must return nothing

# 2. Clone the renamed repo. GitHub 301-redirects the old URL but the
#    new URL is cleaner.
git clone git@github.com:DineroLabs/dinero.git /root/dinero
cd /root/dinero
git fetch origin
git checkout <RELEASE_COMMIT>

# 3. Build dinerod (the standard server build command, per memory).
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target dinerod -j$(nproc)

# 4. Verify the new binary.
./build/dinerod --version   # should report 8.0.0 + commit hash

# 5. Update the systemd unit to point at the new binary path.
sed -i.bak 's|/root/Dinero-Coin/build/dinerod|/root/dinero/build/dinerod|g' \
    /etc/systemd/system/dinerod.service
systemctl daemon-reload

# 6. Start the new binary.
systemctl start dinerod.service
sleep 30

# 7. Verify it reached tip cleanly (no IBD restart, no safe mode,
#    no orphan).
dinero-cli getblockchaininfo | jq '{blocks, headers, verificationprogress}'
dinero-cli safemode.status

# 8. Watch for ~15 minutes; confirm getblockcount advances and matches
#    the rest of the fleet.
for i in 1 2 3 4 5; do
    sleep 180
    dinero-cli getblockcount
done

# 9. Leave /root/Dinero-Coin/ in place untouched as rollback artifact.
ls -la /root/Dinero-Coin/build/dinerod   # the prior binary
```

**Rollback per-node (if step 7 or 8 surfaces a problem):**

```bash
systemctl stop dinerod.service
sed -i.bak 's|/root/dinero/build/dinerod|/root/Dinero-Coin/build/dinerod|g' \
    /etc/systemd/system/dinerod.service
systemctl daemon-reload
systemctl start dinerod.service
# Old binary is back. /root/dinero/ stays on disk for next attempt.
```

**Node order (lowest blast radius first):**
1. **MO** — password auth, no special role. If the procedure has a
   surprise, it surfaces here. ~30 min including watch period.
2. **CN** — cookie auth, no special role.
3. **VA** — cookie auth, no special role.
4. **LA last** — runs the SV2 pool at `172.93.160.131:4444`. Don't
   touch until MO+CN+VA have been validated successfully. Any downtime
   here stops SV2 block submission.

**CN-specific:** uses cookie auth (no `--rpcuser`/`--rpcpassword` flags
in systemd). Confirm the cookie path still resolves under the new
working directory after the binary path change.

**LA-specific:** before the cutover, optionally drain the SV2 pool
(stop accepting new connections) so in-flight share submissions can
complete. After the cutover, verify the SV2 listener restarts cleanly.

## Phase 6 — v8.0.0-rc1 tag cut and release publication

Pre-flight:

- All 4 fleet nodes on the new binary (Phase 5 complete) with no
  chain anomalies for 24+ hours
- Each node's `/root/dinero` checkout matches `RELEASE_COMMIT`
- All platform artifacts from Phase 3 ready
- SHA256SUMS file generated
- Release notes drafted (template below)

**The tag cut itself:**

```bash
cd /Users/haydarevich/src/_rc/consolidate
git fetch origin
git checkout dinero-main   # the renamed monorepo's default branch
git pull
git log --oneline -1   # confirm head equals RELEASE_COMMIT and matches artifacts

git tag -a v8.0.0-rc1 \
        -m "Dinero v8.0.0-rc1 — first unified release from the monorepo"
git push origin v8.0.0-rc1
```

**GitHub release on `DineroLabs/dinero-releases`:**

1. Create a new release pointing at the `v8.0.0-rc1` tag.
2. Upload all Phase 3 artifacts (DMG, Windows installer, .deb, 8
   Linux tarballs).
3. Upload `SHA256SUMS-v8.0.0-rc1` (signed with the operator's GPG key
   if available).
4. Publish.

**Release notes template:**

```
# Dinero v8.0.0-rc1

First release from the unified DineroLabs/dinero monorepo. The
prior DineroLabs/Dinero-Coin, DineroLabs/dinero-qt, and
DineroLabs/dinero-solo-miner repositories are now archived; their
v2.x.x tags remain valid for archaeology.

## What's in the box

- **dinerod** + **dinero-cli** — the full Dinero v7 daemon and RPC
  CLI, unchanged from the v2.2.6 release line consensus-wise.
- **dinero-qt** — desktop wallet with embedded dinerod, launches +
  manages the node automatically.
- **dinero-solo-miner** — solo (direct-RPC) miner with the new
  MinerBackend enum. Pick CPU, Metal (macOS), CUDA (NVIDIA), OpenCL
  (AMD/Intel/NVIDIA fallback) via `--backend <name>`. CPU-verified
  hashes ensure GPU-backend bugs only waste mining time, never push
  invalid blocks.
- **dinero-miner** + **dinero-gpu-miner** + **dinero-stratum-worker**
  — Stratum + daemon-side mining tooling, runtime-validated on Windows
  RTX 4060 via the new NVRTC CUDA path (closes the long-standing
  CUDA 12.2 + MSVC 14.44 toolchain mismatch).
- **dinero-seeder** — new peer-discovery crawler for operators
  running DNS-seed infrastructure.

## Network changes

- Address propagation now works end-to-end: every node forwards
  newly-learned addresses to 2 random peers (Bitcoin Core's fanout
  shape), refreshes peer knowledge via periodic getaddr, and persists
  the peer set atomically across restarts.
- Fixed seed list is now per-release-curated (see
  contrib/seeds/seeds_main.txt) instead of inline literals; community
  operators running healthy nodes can be promoted to seeds across
  releases.

## Upgrading

Drop-in replacement for v2.2.6-rcN. Same consensus rules, same v7
genesis, same chain. Restart dinerod against the new binary; peers.dat
and chaindb carry over unchanged.
```

## Post-release watch (first 72 hours)

After `v8.0.0-rc1` is public:

- Monitor the fleet's `safemode.status` every 4h
- Watch SV2 pool block submission rate (LA `172.93.160.131:4444`)
- Watch for community reports on Discord / GitHub Issues
- If any consensus-affecting issue surfaces, the v2.2.6 line stays
  available as the rollback target

If clean for 7 days: cut `v8.0.0` final (re-tag the same commit
without the `-rc1` suffix, regenerate artifacts, re-publish).

If issues surface: cut `v8.0.0-rc2` from a fix commit, repeat Phases
3+6 (Phases 4–5 don't re-run unless the issue is in those phases'
work).

## What this runbook is and isn't

This is the operator-side counterpart to the source-side consolidation
work that lives in commits Phase 1 through Phase E. **No automation
in this file** — Phases 3-6 deliberately keep human-in-the-loop
because they all touch credentials, public state, or production
daemons. Don't script around the verification gates.

Once v8.0.0 final ships, this runbook can be split: the per-release
parts (Phase 3 artifact-building) become a per-release script with
guardrails; the one-time parts (Phase 4 rename, Phase 5 fleet
cutover) get archived as historical record.
