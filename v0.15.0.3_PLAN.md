# v0.15.0.3 Implementation Plan: BlockIndex Population

**Goal**: Enable ChainManager to perform automatic fork selection by populating BlockIndex tree

**Status**: 📋 **Design Phase** (not yet implemented)

---

## 🎯 The Problem

**v0.15.0.2 wired ChainManager**, but it returns early:
```cpp
CBlockIndex* ChainManager::GetBestCandidate() {
    if (block_index_candidates_.empty()) {
        return nullptr;  // ← Returns here currently
    }
    // ...
}
```

**Why**: No `CBlockIndex*` entries exist. BlockAcceptor doesn't create them during block acceptance.

**Solution**: Populate BlockIndex tree from persisted headers.

---

## 📐 Architecture Design (Bitcoin-Aligned)

### What BlockIndex Contains

```cpp
struct CBlockIndex {
    // Navigation
    std::string hash;
    CBlockIndex* pprev = nullptr;  // Parent pointer
    std::vector<CBlockIndex*> children;  // Child pointers (for forks)

    // Metadata (computed from header)
    uint32_t height = 0;
    arith_uint256 chainwork = 0;  // Cumulative PoW

    // Status flags
    enum Status {
        VALID_HEADER    = 0x01,  // Header validated
        VALID_TREE      = 0x02,  // Parent linkage valid
        VALID_SCRIPTS   = 0x04,  // Scripts validated
        VALID_CHAIN     = 0x07,  // Fully validated (HEADER | TREE | SCRIPTS)
        BLOCK_FAILED    = 0x08,  // Marked invalid
    };
    uint8_t status = 0;

    // Header data (opaque to BlockIndex)
    BlockHeader header;  // 112 bytes (includes Utreexo commitment)
};
```

**Key Insight**: Utreexo commitment is stored in `header`, but BlockIndex never interprets it.

## 🔧 Implementation Strategy

### Phase A: On-Demand Population (v0.15.0.3)

**When**: During block acceptance
**Where**: `BlockAcceptor::ConnectBlock()` (after successful UTXO updates)

```cpp
// In BlockAcceptor::ConnectBlock(), after WriteBatch commit:

// 1. Create BlockIndex entry
CBlockIndex* block_index = new CBlockIndex();
block_index->hash = block.blockHash;
block_index->height = newHeight;
block_index->header = block.header;  // Full 112-byte header

// 2. Compute chainwork from parent
CBlockIndex* parent = FindBlockIndex(block.prevBlockHash);
if (parent) {
    block_index->pprev = parent;
    block_index->chainwork = parent->chainwork + GetBlockProof(block.header.bits);
    parent->children.push_back(block_index);
} else {
    // Genesis or orphan block
    block_index->chainwork = GetBlockProof(block.header.bits);
}

// 3. Mark status
block_index->status = CBlockIndex::VALID_CHAIN;  // Fully validated

// 4. Add to global map
g_block_index_map[block.blockHash] = block_index;

// 5. Notify ChainManager
if (dinero::g_chain_manager) {
    dinero::g_chain_manager->AddBlockIndex(block_index);
}
```

**Result**: BlockIndex grows incrementally as blocks are accepted.

### Phase B: Startup Reconstruction (v0.15.0.4+)

**When**: Daemon startup (after ChainDB init, before RPC server)
**Where**: New function `ChainManager::RebuildBlockIndexFromHeaders()`

```cpp
// In DaemonApp::Init(), after ChainManager initialization:

if (dinero::g_chain_manager) {
    auto chain_db = chainstate->chainDB();
    dinero::g_chain_manager->RebuildBlockIndexFromHeaders(chain_db);
}
```

**Implementation** (in `src/consensus/chain_manager.cpp`):

```cpp
void ChainManager::RebuildBlockIndexFromHeaders(ChainDB* chain_db) {
    dinero::g_logger.info("Rebuilding BlockIndex from stored headers...");
    auto start = std::chrono::steady_clock::now();

    // Step 1: Load all headers from ChainDB (ordered by height)
    std::vector<std::pair<uint256, BlockHeader>> headers;
    auto status = chain_db->forEachHeaderHeight([&](int height, const uint256& hash) {
        auto header_result = chain_db->getHeader(hash);
        if (header_result.status() == Status::Ok) {
            headers.push_back({hash, header_result.value()});
        }
        return true;  // Continue iteration
    });

    dinero::g_logger.info("Loaded " + std::to_string(headers.size()) + " headers");

    // Step 2: Create BlockIndex entries
    for (const auto& [hash, header] : headers) {
        CBlockIndex* idx = new CBlockIndex();
        idx->hash = hash;
        idx->header = header;  // Store full 112-byte header
        idx->status = CBlockIndex::VALID_HEADER;  // Assume valid (was persisted)

        g_block_index_map[hash] = idx;
    }

    // Step 3: Link parents (build DAG)
    for (auto& [hash, idx] : g_block_index_map) {
        auto parent_it = g_block_index_map.find(idx->header.prevBlockHash);
        if (parent_it != g_block_index_map.end()) {
            idx->pprev = parent_it->second;
            parent_it->second->children.push_back(idx);
        }
    }

    // Step 4: Compute height and chainwork (walk from genesis)
    CBlockIndex* genesis = g_block_index_map[GetGenesisHash()];
    if (genesis) {
        genesis->height = 0;
        genesis->chainwork = GetBlockProof(genesis->header.bits);

        std::deque<CBlockIndex*> queue = {genesis};
        while (!queue.empty()) {
            CBlockIndex* parent = queue.front();
            queue.pop_front();

            for (CBlockIndex* child : parent->children) {
                child->height = parent->height + 1;
                child->chainwork = parent->chainwork + GetBlockProof(child->header.bits);
                queue.push_back(child);
            }
        }
    }

    // Step 5: Identify active chain tip from ChainDB
    auto tip_result = chain_db->getTip();
    if (tip_result.status() == Status::Ok) {
        std::string tip_hash = tip_result.value().hash;
        active_tip_ = g_block_index_map[tip_hash];
    }

    // Step 6: Populate candidate set (all valid leaf nodes)
    for (const auto& [hash, idx] : g_block_index_map) {
        if (idx->children.empty() && idx->status != CBlockIndex::BLOCK_FAILED) {
            block_index_candidates_.insert(idx);
        }
    }

    auto elapsed = std::chrono::steady_clock::now() - start;
    dinero::g_logger.info("BlockIndex rebuilt: " +
                          std::to_string(g_block_index_map.size()) + " blocks in " +
                          std::to_string(std::chrono::duration_cast<std::chrono::milliseconds>(elapsed).count()) + "ms");
}
```

**Cost Analysis** (1 million blocks):
```
Header reads:  112 MB sequential I/O    ← trivial
Memory:        ~200 bytes * 1M = 200 MB  ← acceptable
Computation:   O(n) parent linking      ← seconds
Result:        Fast startup
```

## 🗂️ Global Data Structure

```cpp
// In include/consensus/block_index.h

namespace dinero {

// Global BlockIndex map (populated on startup + incrementally)
extern std::unordered_map<uint256, CBlockIndex*> g_block_index_map;

// Helper functions
CBlockIndex* FindBlockIndex(const uint256& hash);
arith_uint256 GetBlockProof(uint32_t nBits);  // Convert difficulty to chainwork

} // namespace dinero
```

**Thread Safety**: Protected by ChainManager mutex (single-threaded block acceptance)

**Memory Management**: BlockIndex entries never deleted (except on shutdown)

---

## 🔐 Why This Is Safe

### 1. BlockIndex Is Metadata-Only

**BlockIndex does NOT validate**:
- ❌ UTXO correctness
- ❌ Script execution
- ❌ Utreexo commitments
- ❌ Transaction validity

**BlockIndex ONLY tracks**:
- ✅ Chain linkage (DAG)
- ✅ Cumulative PoW (chainwork)
- ✅ Fork structure

**Validation happens in**: `BlockAcceptor::ConnectBlock()` (unchanged)

---

### 2. Utreexo Commitment Is Opaque

```cpp
// BlockIndex stores the full header:
idx->header.utreexoCommitment = "...";  // 32 bytes

// But never interprets it. Validation happens elsewhere:
// BlockAcceptor::ConnectBlock() checks Utreexo commitment
// BlockIndex just carries it as payload
```

**Separation of Concerns**:
- BlockIndex → Fork selection (chainwork)
- BlockAcceptor → Validation (scripts, UTXO, Utreexo)

---

### 3. Reconstruction Is Deterministic

**Given**: Persisted headers in ChainDB
**Output**: Identical BlockIndex tree every startup

**Why**: Header data is immutable. No heuristics, no randomness.

    CBlockIndex* parent = new CBlockIndex();
    CBlockIndex* child = new CBlockIndex();

    child->pprev = parent;
    parent->children.push_back(child);

    EXPECT_EQ(child->pprev, parent);
    EXPECT_EQ(parent->children.size(), 1);

## 🧠 Key Design Principles

1. **BlockIndex is ephemeral** (rebuilt from headers on startup)
2. **Headers are canonical** (persisted in ChainDB)
3. **Utreexo is opaque** (BlockIndex doesn't interpret it)
4. **Validation is separate** (BlockAcceptor owns correctness)
5. **Memory is acceptable** (200 bytes * 1M blocks = 200 MB)
