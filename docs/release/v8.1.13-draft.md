# Dinero v8.1.13 — draft release notes

**Unreleased. Not an activation or upgrade announcement.** Final source commits,
downloads, checksums, platform availability and activation details will be added
only after [release qualification](../specs/v8.1.13-release-qualification.md).
No release date or mainnet activation height is committed by this draft.

## Orchard private payments

The candidate adds an Orchard pool using Halo 2 and the pinned Orchard 0.16 Rust
backend. Desktop integration provides account discovery, receive addresses,
shielding, private transfers, unshielding, balances and incoming-payment history.
The final desktop packages must explicitly include the Orchard screens and the
matching backend; their presence in source is not sufficient.

Payment status distinguishes proof preparation, submission and confirmation.
Rejected submissions are not displayed as paid. Retrying a stored request keeps
its original identity and transaction intent. Wallet/account binding prevents a
request from silently applying to a newly selected wallet, and unavailable
balances display as unknown. Installed application behavior remains part of the
release qualification gates.

Orchard is a new pool. This release must not be described as automatically moving
legacy shielded balances into Orchard. Preserve existing wallets and backups;
restoring a recovery phrase uses a new wallet name and does not overwrite an
existing wallet.

## Coordinated network upgrade

The candidate includes the joint compact-proof, 60-second block and Orchard
release profile. Public activation remains unset. These rules must be scheduled
consistently, with the reviewed Orchard branch ID, after qualification and a
coordinated upgrade window. The final announcement will explain the chosen
height and required node/miner/app versions.

Block-based policies do not necessarily preserve their previous elapsed time
when block spacing changes. Final documentation must describe proof refresh and
confirmation behavior without promising a fixed wall-clock completion time.

## DIN/BTC swaps

The integration includes the local swap engine and desktop Swap tab. Swap
operation remains opt-in on the node. macOS and Linux release payloads are
intended to include `dinero-swap-tower`; final package contents and supported
configuration must be verified before publication. Do not advertise a Windows
tower package without its separate platform support and qualification.

Refund timelocks open a refund path; they do not disable a competing claim path.
Prompt claim/refund handling and the reviewed tower policy matter. The release
must not promise a guaranteed claim window or automatic recovery regardless of
chain stalls, fees or operator availability. Private covenants and unresolved
vault fee-payer behavior are not advertised as completed features here.

## Reliability and dependency maintenance

The candidate includes wallet ownership/recovery hardening and typed Orchard
admission and chain-state integration. Final notes must identify the additional
block-download and mining fixes included by the final source manifest. Each final artifact must be tied to that source and
its qualification record; predecessor CI success alone is insufficient.

Rust dependency advisory scanning checks for published advisories, alongside
pinned dependencies and review of local patches. It does not establish that all
security defects are known or absent.

Mac packaging now filters Qt plugins in a private deployment directory instead
of temporarily changing the shared Qt installation. Final signing and installer
qualification remain separate steps.
