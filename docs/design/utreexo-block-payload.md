# Utreexo block transport capture

The actual legacy OnUtxoBlock handler now obtains one owned envelope through DecodeUtreexoBlockPayload before deserializing inner proofs or touching queues and storage. This reusable boundary separates wire framing from the full-forest handler so compact historical reception can reuse the transport contract without constructing a legacy StatelessNode.

Only documented versions 2 and 3 are accepted. The existing 5 MiB envelope, 4 MiB block, 1 MiB batch-proof and 512 KiB transition-proof limits remain. Each length is little-endian and checked against remaining bytes before copying. Version 3 includes its transition length even when zero. Truncation, trailing bytes, unsupported versions, mismatched body identity and envelopes with neither proof section refuse.

The result owns its fields, including exact block bytes. Only the fixed 128-byte header is parsed here. Full transaction parsing remains in the existing handler after the complete outer envelope is captured. Height and advertised root remain untrusted. The decoder does not authenticate either proof, certify a canonical block, persist anything or acknowledge download completion. Existing inner proof decoders and selected-chain validation remain separate; their supported historical encodings are not recanonicalized here. Malformed optional transition framing now refuses rather than falling back to a batch proof. Existing downstream validation, synchronization, storage, retry and acknowledgment code is unchanged.

The original three component cases cover v2/v3 fields and owned copies, truncation/trailing/version refusal, and length/body-identity refusal. Opaque proof bytes explicitly exercise transport only. This draft is unapplied and uncompiled: no original-red, runtime, complete historical compact reception or whole-node qualification is claimed. The full-storage startup guard remains. Real compact historical proof validation and startup composition remain required before release.

V3 additionally changes the actual Block::Deserialize caller: an impossible transaction count larger than the remaining byte count refuses, and the transaction vector grows only after each transaction decodes. The input count is never passed to reserve. This preserves the existing CompactSize encodings and optional absent-Utreexo flag. Two additional component cases check those compatibility rules and small incomplete bodies; they are correctness checks, not a measured allocation bound or a claim that the predecessor fails them. No large-count or resource-exhaustion probe is used. Inner transaction/proof allocations and the repeated remaining-byte copy still require separate review; no whole-receive memory or CPU bound is claimed. V1 and V2 remain uncompiled predecessors.
