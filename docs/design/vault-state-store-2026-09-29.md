# Wallet-bound vault state transactions

The explicit CreateNewService factory creates a fresh random vault identity and empty state under the actual selected WalletService/WalletManager session and recovery seed. OpenExistingService requires a supplied existing identity and authenticates it; absent storage/rows never create or replace an owner. Factory candidates are fully allocated and restored before checked COMMIT returns them. These factories are not yet installed into daemon startup or RPC.

The versioned DNVS02 snapshot (with DNVS01 read compatibility) carries all present ledger entries, deposit observations/lifecycle, withdrawal requests/states and policies. Bounded canonical decoding checks complete input, types, ordering and duplicates. Actual ledger replay reconciles every present deposit/request lifecycle with its exact ledger binding, including pre-credit reverted deposits. Existing numeric guards and economic formulas are retained; broader loss accounting is not certified. Limits64MiB/1million rows refuse rather than truncate and are not resident/load qualification.

A checked FULL SQLite transaction holds the real database lease and64-byte recovery seed. AES256-GCM binds network/genesis, persistent wallet identity, vault identity, revision and predecessor digest. Required SQL reads/writes/types/terminal completion and COMMIT are checked; borrowed transactions refuse. Every successor compares the existing revision/ciphertext before replacement. Plaintext/key buffers are scoped and cleansed. This is current authenticated state plus predecessor binding, not a retained revision archive or catalog/deletion/backup-rollback certificate.

Restored service mutations acquire wallet ownership before the service mutex, prepare the whole candidate, commit its encrypted snapshot, then perform nonthrowing live swaps. A stale session or divergent durable/live state refuses. Selected-chain capture precedes wallet ownership. Existing in-memory service construction remains separate. Durable withdrawal dispatch uses the separately described retained wallet-payment bridge: Signing commits before external work and the exact retained payment commits before live publication. Factories without that bridge refuse signing. Production runtime integration remains open.

Nine patched-path cases cover canonical snapshot/replay/refusals and actual wallet-bound SQLite create/reopen, complete saved pending requests, authenticated identity/domain/refusal, required write and commit rollback, denied reads, stale sessions, and caller-owned transactions. Component chain callbacks are synthetic. No unsafe-original controls, deadlock/race reproductions, whole-node/power-loss, multiprocess, deletion completeness or readiness claim. The earlier12-project-C++/45-case snapshot preflight is narrower and does not qualify the database implementation.

Whole create/restore, durable catalog/high-water, actual runtime/RPC attachment, withdrawal settlement/fees/cancellation/lineage and loss invariants, notification provider, whole-node/platform/load gates remain open. Mainnet unset/no deployment. Locally qualified in the combined durable-vault batch.
