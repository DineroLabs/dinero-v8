# Selected-chain exclusion during mining construction

Owned daemon BlockAssembler operations acquire one configured selected-chain guard before pool access and retain it through the final template/job result. The production weak-service factory retains ChainstateService and its existing recursive activation lock. Factory capture uses a short separate mutex; invocation and destruction occur outside that mutex. A configured unavailable owner refuses before pool acquisition or template-state mutation. Unconfigured component callers retain their existing external serialization contract.

Actual getblocktemplate acquires the same activation lock only after longpoll returns, before readiness and pool use, through response serialization. Actual mining.getjob uses the same ordering. CreateJob treats an explicit parent as an expectation that must equal the current durable selected tip; a recorded old header cannot select a different parent while the operation reads current coins/forest.

This excludes concurrent activation/reorg/promotion for covered operations. It does not certify independent historical parent provenance, synchronize all assembler setters, make shutdown teardown globally owned, or repair wallet-scoped providers/CSN pre-base semantics. Raw constructor/setup callers remain externally serialized. Mainnet activation unset; production notification provider and release gates remain open. Qualification must use benign patched-path cases and actual daemon integration; no unsafe original or synchronization-removal control.
