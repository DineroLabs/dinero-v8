# Shared ordinary and Orchard reservation ownership

## Change

The prepared ChainstateService payment entry captures the immutable account replay before selected-chain and wallet locks. It requires the caller's exact index lifetime use and rejects a borrowed outer wallet or selected owner. It rechecks the captured head, EOF and exact tip under the selected writer lock, then holds that lock through the wallet transaction. Service lifetime and WalletUse remain the caller's responsibility.

The wallet owner begins a checked FULL transaction, authenticates the generated catalog and all current/reached/retained owners, and fully restores nonempty account inventories at the captured head. Existing archive reconciliation reactivates operations whose selected completion cause disappeared, using actual retained branch bodies. It then rereads the authenticated inventory and ordinary pending owner, rejects shared or already reserved inputs, signs with exact keys, and appends the signed payment/history/reservations. COMMIT precedes returning a signed result. Unknown recovery/missing catalogs refuse; no account or identity is created.

The ordinary signer has a private friend bridge for caller-owned key/request reads and payment append. Existing public signing entry points retain their previous contract. The private append uses a checked savepoint inside a FULL transaction; caught errors cannot leak partial history or payment writes. The outer owner rolls back any archive reconciliation if signing or append fails. Existing baseline preservation and arbitrary-history invalidation remain unchanged.

## Tests and evidence

Eight backend-ON cases are written for the actual service owner using an isolated genuinely signed and mined ordinary funding coin: generated-empty and nonconsecutive-account commits/reopen; a real Orchard shield plan reserving that same input; history/COMMIT refusal with a SQL-free hook observing the selected lock; denied inventory reads and borrowed transaction refusal; lagging/missing/unknown catalog refusal. Three cases also call the actual sendmany/sendtoaddress handlers with canonical funding and real mempool admission or reservation refusal. The CI lane requires the enabled 180-second registration and every exact case marker.

Source and tests are prepared together. They have not been compiled or executed; no initial RED or passing qualification is claimed. The active checkout remains frozen for earlier qualification. Fresh ON/OFF full targets, all affected component cases, complete linked project C++ instrumentation maps and exact-source Linux qualification remain required.

## Remaining integration

Both ordinary payment RPCs route final retention through the service owner. Exact retained explicit-request retries still return before chain access, selection or signing. Preview/raw signing behavior and normal public signing callers are unchanged. The reverse transparent-input Orchard shield reservation path still needs this shared owner. Account archive reactivation with a shared transparent input still needs an executed real-fork regression. Canonical source admission still refuses unknown legacy/recovered account catalogs; complete authenticated recovery policy remains required. The separate pre-activation protocol branch preserves ordinary signing only after checked selected/durable tip and explicit absent runtime/retirement state. Source errors never choose it; any retained delivery history uses canonical validation even after rollback below activation. Within that pre-activation branch, a FULL wallet transaction refuses declared or stored Orchard accounts, then signs and appends using the existing identity. Absent old/recovery catalog data does not become a completeness certificate, new-pool permission or identity-generation authority. Recorded owners need replay. The old RPC test fixture now initializes actual isolated chain state instead of injecting just an index; all original assertion bodies are unchanged. This change therefore does not establish complete global reservations, balance selection, shield/send/unshield, whole-node restart/reindex/reorg or release readiness. Current bounds remain refusal limits, not load qualification. Mainnet activation stays unset.
