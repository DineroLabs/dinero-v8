# Isolate the pool accounting library from its chain-source adapter

The exact c581 Linux root and Core Heavy builds failed because generic PoolManager linked the canonical maintenance adapter, which pulled ChainstateService and its daemon-only config, mempool and vault dependencies into unrelated storage/accounting test binaries. Completed logs record one root target and nine heavy target failures. Repeating static archives resolved the earlier two adapter symbols but did not establish a valid dependency boundary.

The public setChainstateSource entry now lives with the concrete canonical adapter. It atomically binds the weak source and a private function pointer to the same checked reconciliation method. Callers still supply only a real ChainstateService; there is no public arbitrary accounting callback. The manager captures/pins both under its existing mutex and invokes the adapter after releasing that mutex. Missing/expired source or missing binding refuses. Start/stop, lifecycle ownership, source validation, accounting transactions, payment ordering and existing fixtures are unchanged.

The generic pool archive no longer references the canonical adapter or depends on dinero_core. Real daemon/integration callers that use setChainstateSource still link the complete canonical adapter. No new stub, suppression, whole-archive option or duplicated implementation is added.

The exact nine failed targets are mandatory in the root Linux build and an enabled execution lane, with inventory and logs retained. Qualification requires fresh ON/OFF full daemon and all affected targets plus prior cases and complete linked-project instrumentation of both manager and real adapter. Local compiler success cannot establish GNU/ELF behavior; fresh exact-source Linux remains required. Fresh ON/OFF full daemon and all twelve declared component targets passed; 43 prior selected CTests plus nine actual Linux regression targets passed in each configuration. All linked project C++ in replay, wallet and separate DaemonApp graphs was rebuilt with ASan/UBSan: 93 replay and 85 wallet GTest cases passed, plus actual full/CSN DaemonApp modes. The nine additional regression binaries were executed normally and are outside those sanitizer graphs. Existing source checks and test assertions/deadlines are unchanged. Exact-source GNU/ELF CI remains required; no release-readiness or activation claim. Mainnet unset; no deployment, activation or release-readiness claim.
