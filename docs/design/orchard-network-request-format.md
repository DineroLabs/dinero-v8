# Orchard network request format

Unapplied, uncompiled draft. This changes the actual parallel and ordered daemon download callbacks to use one request-format policy. Full storage and store-only backfill retain raw block requests. Unscheduled stateless operation retains legacy block-plus-proof requests. With an Orchard schedule, stateless tip requests need an exact known header, matching optional scheduler height and stable selected context. Historical heights retain legacy proofs. Orchard heights request the typed raw envelope. Actual compact storage ownership remains checked by the existing receive/ingress path.

Choosing a request format does not validate a block, acknowledge a download or publish readiness. Unknown headers, wrong heights, invalid profiles and missing header/service contexts refuse. A stopped service can still yield the known wire format, but the receiving owner refuses the body and cannot acknowledge it. The request selector never takes the selected-chain or service-lifetime lock: the parallel scheduler calls it while holding its request queue mutex. The existing full-storage startup guard and legacy stateless scheduler drain protection remain unchanged. Historical proof ingress, explicit compact scheduler mode, canonical queue/header startup, maintenance and mining composition still need completion before enabling compact DaemonApp startup.

Three new component cases are defined, one available with the wallet backend disabled. They are not compiled or executed yet. They exercise the shared policy with actual compact service/header fixtures; they do not execute DaemonApp transport callbacks or use network sockets. Both actual callback edits require fresh full ON/OFF compilation, current-map sanitizer qualification and subsequent configured-composition testing. No original failing-test claim, IPC, production activation or release readiness follows from this draft.
