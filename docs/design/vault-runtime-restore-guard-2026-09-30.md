# Vault initialization refuses incomplete legacy recovery

The legacy runtime previously read a ledger file, discarded the returned entries and published an empty service. It also caught configured storage failures and continued, and an invalid operator address became an unconfigured observer. These behaviors could report initialization without the requested owners.

Initialization now prepares operator binding, configured store, readers, backend, service and status text in local owners. Nonempty legacy ledger or idempotency files and nonregular storage refuse before append-open/backend construction, preserving their bytes. Configured empty-store open/read and invalid operator failures propagate. Parent directories for a new configured empty store are created explicitly. Nonthrowing swaps publish prepared state; the initialized flag is last. A disabled invocation returns false, successful or already initialized invocations return true, and daemon RPC wiring reports that result. Enabled failures propagate through its existing failure return.

This is a fail-closed guard, not a legacy-to-wallet state migration. An empty or missing file is not evidence that historical vault ownership never existed. The remaining legacy in-memory initializer is still not a durable runtime or a release readiness certificate. Complete wallet-owned state attachment, operator policy, global catalog/deletion/backup guarantees, withdrawal settlement/reorg/fee accounting and installed notification acknowledgments remain separate work. Concurrent filesystem replacement and multiprocess startup are not qualified by this change. No source or file reconstruction, truncation, new historical identity, fee/label fabrication or reset-to-ready behavior is introduced.

Four patched component cases cover disabled/missing readers, exact real legacy-ledger preservation, sidecar/malformed-file refusal, and failed preparation followed by an explicitly selected fresh path. Existing fixture assertions and deadlines remain. Locally qualified in the combined durable-vault batch.
