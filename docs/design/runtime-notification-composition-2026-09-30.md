# Runtime notification composition

Locally qualified with fresh full daemon and declared replay targets ON/OFF, eight actual selected CTests each, and all 37 selected ON cases in a fresh complete linked-project ASan/UBSan graph. Six new composition cases execute ON and three OFF. External/Rust/C/PQClean are uninstrumented; macOS LSan is off; daemon/OFF are outside the sanitizer graph. Exact Linux and release qualification remain separate. This component is not installed in DaemonApp.

An immutable declaration lists each remaining consumer family exactly once: wallet/readmission, pool accounting, chain/time/transaction oracles, vault and extra wallet notifiers. Null explicitly declares an absent family. The trusted daemon composition owner must derive those declarations from actual configured owners; this class cannot prove configuration completeness. Configured unsupported consumers must not be declared absent. Chainstate already owns local mempool, bridge and relay-tip publication; those are not repeated here.

Every present consumer prepares the same typed body before canonical commit. Any refusal or exception destroys all prepared handoffs without block publication. Handoffs retain their consumer owners. Successful publication invokes each prepared token only after durability. Reorg preparation shares one immutable plan. Partial preparation unwinds with incomplete lower-bound progress; zero counts never authorize deletion or prove no durable work. Chainstate retains the plan before returning its transition and before first rollback. Consumers use that durable source on restart.

The wallet adapter and prepared tokens own only a separate wake mailbox, never the worker or its source. Publishing or destroying a token cannot join the worker. The daemon lifecycle owner stops the worker outside chain/wallet/runtime ownership. Requests after stop are ignored; the next start always scans retained work. A wake is neither synchronous recovery nor acknowledgement. Startup recovery, retained-intent readmission and actual wallet receipts remain owned by the existing worker and canonical source.

Six patched-path cases cover complete declarations, prepare/refusal/exception cleanup, handoff ownership, a mailbox surviving an explicitly stopped worker, shared reorg plan/progress, actual typed block commit and encrypted wallet replay after the real notification. No unsafe original/race/churn/barrier reproduction or synchronization-removal control is used.
