# Exact Orchard download storage and canonical drain

Locally qualified. The actual consensus download scheduler accepts exact Orchard bytes only against its known header/height and tip-download inventory, checking bounded framing, coinbase height and transaction/witness identity commitments before durable flatfile storage. Storage is not proof validation or canonical acceptance. The existing flatfile write, RAM receipt and optional metadata callback are separate; metadata failure can leave a retained prefix, and this is not a complete restart catalog. Unknown headers/download entries refuse before full-body decoding. Missing storage, unsupported profile, stateless and history-backfill paths refuse this entry point.

The ordered drain reads exact typed bytes at the recorded position and rechecks identity. It captures the offered hash/height/position, releases its mutex for canonical validation, then re-finds that exact CONNECTING record before acknowledging a result. A single active drain prevents recursive or concurrent duplicate application. Changed download inventory cannot inherit an old callback result. Historical connection callbacks also execute outside the mutex; existing refusal/retry policy remains. Read failures request the body again; operational failures retain it. Production wiring acquires the existing ingress service from a weak owner and uses its queued full validator, checking connected hash/height before returning success.

Four ON/one OFF patched-path cases cover real proof-bearing storage, provider refusal/retry through the actual queue and canonical owner, exact reopen, public scheduler calls from the callback, changed-inventory refusal, missing storage and exact framing, and no historical fallback. Two existing scheduler targets also run unchanged. No original/race/synchronization-removal controls. Fresh full ON/OFF and all-linked project sanitizer qualification required.

This installs the drain adapter; network OnNewBlock classification, relay and parallel-download bookkeeping, typed backfill/CSN, side-branch state validation, automatic reorg readmission and production notification provider remain open. Mainnet unset/release incomplete.

The typed decoder is compiled into the actual scheduler only when its real backend library is linked. Both standalone ON scheduler targets link the same decoder. OFF receipt refuses and OFF drain retains pending typed state without acknowledgment; historical decoding is unchanged.
