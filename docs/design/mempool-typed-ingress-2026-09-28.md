# Owned incoming transactions and orphan retry

TxRelayManager captures historical inputs into the existing immutable mempool body before invoking callbacks. Typed and historical submission setters replace one callback owner; legacy validators never receive Orchard by conversion. ITxIngress has an explicit typed entry point which preserves historical virtual Submit and returns UNAVAILABLE for absent family support. DaemonApp uses that typed entry point with P2P origin. Incoming wire parsing remains historical; this change does not enable Orchard admission.

TxOrphanPool stores immutable bodies and indexes the actual parent transaction IDs of their inputs. It retains current count, byte, per-peer and expiry limits, the historical resource envelope and the canonical Orchard wire bound. Insertion stages rollback copies of its bounded maps so an allocation or eviction failure cannot leave partial indexes/counters. A historical inventory request refuses mixed bodies rather than returning a partial vector. Captured bodies remain available after removal.

Actual relay orphan resolution retains MISSING_INPUTS and UNAVAILABLE results for later parent arrivals. Accepted or definitely rejected orphans retain the existing removal behavior. This preserves a child still missing its second parent after the first arrives. No orphan entry certifies signatures, proof validity, anchors, nullifiers, selected-chain state or admission.

Canonical historical admission now propagates a typed validation result. The actual coin read distinguishes checked absence from unavailable storage before any fallback; only checked absence may use the existing conflicted-parent recovery. Missing inputs return MISSING_INPUTS to relay, rather than the generic INVALID_TX which previously prevented orphan retention. Failed service/chain acquisition, storage errors and ambiguous absent pre-base resolution return UNAVAILABLE. Script, fee, resource, replacement and consensus checks still run before admission. Input amount/script/confidential metadata comes from the same captured coin. The legacy optional pre-base resolver cannot prove why no coin was returned, so that result is conservatively unavailable.

The lookup classification also distinguishes an invalid output index on a known parent from a provider error carrying the same low-level status. The former is INVALID_TX; the latter remains UNAVAILABLE. The isolated fixture installs an owned read-error view through a test-only friend, with no production view setter.
