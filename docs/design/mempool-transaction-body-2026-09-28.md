# Owned mempool transaction bodies

`MempoolEntry` retains an immutable `MempoolTransaction` owner. Historical bodies retain an actual copied `Transaction`; the Orchard backend adapter retains an actual immutable `TransactionEnvelope`. Neither converts implicitly into the other. A default owner has no body and refuses reads. Explicit family access rejects the wrong family. Common accessors retain exact IDs, wire bytes, weight, input outpoints and explicit fee information.

Canonical historical admission captures its body before selected-chain acquisition, validation or pool effects. Entry insertion and post-admission callbacks retain that same owner. The transparent synthetic insertion helper also captures its input. Entry input metadata comes from the owned body once, rather than appending a second independent input list at insertion. Existing entry copies retain their body after the pool removes or replaces the live entry.

The Orchard entry constructor requires the supplied fee to equal the envelope's explicit fee. This is a body and metadata consistency check, not proof verification or admission. The envelope adapter is linked only with the real backend. The common historical owner compiles without that backend.

Current historical-only RBF, mining, wallet, compact-block, RPC and persistence consumers request `Historical()` explicitly. They do not receive a fabricated historical transaction for an Orchard body. The legacy disk format and optional gRPC transport retain that explicit family restriction. Optional gRPC source adaptation does not establish runtime or build qualification when gRPC is disabled.
