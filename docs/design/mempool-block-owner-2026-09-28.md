# Prepared mempool block reconciliation

Actual typed transparent block connect/disconnect prepare complete local pool updates under the pool mutex. The move-disabled, thread-affine prepared object retains that lock. Preparation temporarily applies the existing typed reconciliation, then nonthrowing swaps restore live state and retain the proposed state separately. Allocation or ordinary exceptions restore prior state before releasing the lock. Abandoning the prepared object discards its proposal. PublishAfterCommit performs nonthrowing swaps and releases the pool lock. Existing block callbacks now use this owner for their immediate publication path.

The shared admission rollback owner also retains the local accumulator root and height. Transaction entries carry proof staleness and cached payloads; entries, spent/fee/time/dependency/exclusion indexes, overlay and counters move together. The Mempool must outlive its prepared object; preparation/publication/destruction occur on one thread. Callers hold selected-chain ownership before preparation and must not reenter pool APIs while retaining the prepared object. A published object cannot be published twice.

Benign patched logger exceptions exercise typed conflicts/confirmation and proof-cache rollback/retry; an additional fixture abandons and publishes actual prepared objects. No unsafe-original, deadlock/race, synchronization-removal or exploit reproduction is run. Successful local tests do not prove every allocator failure or complete consumer delivery.

This does not install the production notification provider, authenticate the supplied effects independently, persist a pool receipt or roll back an already committed canonical chain. That provider must prepare all configured consumers and retain its canonical recovery source before activation. Orchard admission/readmission/relay/mining remain open. Full-state copies scale with pool size; load/resident qualification remains open. Mainnet activation remains unset.
