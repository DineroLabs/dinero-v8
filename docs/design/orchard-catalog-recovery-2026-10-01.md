The production ChainstateService wallet recovery adapter now selects catalog-aware
recovery. Each inventory read authenticates the generated catalog, reconciles every
declared account and reached archive, and validates retained envelopes and recorded
account predecessors under one checked FULL transaction. Missing or unknown catalogs
refuse before effects. Catalog content/revision joins the existing account/archive
and transparent-store rechecks around source reads and before each recovery batch.
The result includes the captured catalog revision; it is not lasting spend readiness.

An authenticated generated empty catalog permits existing transparent baselines to
replay without creating Orchard schema or accounts. Empty means both current and
retained tables contain no rows; partial schema or unsupported versions refuse.
Absence alone is never an empty-owner certificate. A populated catalog with a deleted
account or missing required history refuses rather than rebuilding it.

retains earlier committed prefixes for owned retry. Existing explicit one-account
