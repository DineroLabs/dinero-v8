One canonical inclusion moves each complete attempt's worker pending amount to total paid and marks its exact payouts PAID. If an existing settlement block is no longer canonical, the same transaction restores pending credit and CONFIRMED payout state while retaining the immutable attempt, allocation membership and authenticated wallet body summary. It cannot authorize a second payment. Missing transaction-index data alone is not proof of absence: an unchanged old canonical block preserves accounting. Missing/unavailable source never proves disconnection. A stopped or inconsistent source refuses. Source loss after the snapshot cannot interleave with accounting because the selected owner remains held through commit. No external wallet, relay or user callback is invoked in that DB-only owner.

The legacy chainstate pool notifier now performs only pool-local confirmation/allocation work under the selected owner. An acknowledgement that all pool work is current is not introduced.

## Limits

PAID means observed inclusion and is reversible; it is not finality or a lasting canonical certificate. This batch does not add a confirmation-depth product policy. Pool tables remain checked durable metadata rather than an authenticated completeness catalog. Deletion/backup rollback, independent canonical eligibility of source allocations, source-block orphan debt and uncertain-attempt operator recovery remain open. An in-flight source-block reversal still refuses. Missing transaction-index entries can defer a new settlement even when its transaction is included. No chain-wide absence, resubmission or regeneration permission is inferred. No notification provider is installed; mainnet activation remains unset.
