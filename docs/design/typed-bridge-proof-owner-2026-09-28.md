# Typed transaction bridge proof snapshots

The actual bridge getdata path captures one immutable typed pool entry under selected-chain and service lifetime ownership. The selected-chain lock covers provider metadata and forest proof capture, and is released before outbound callbacks; PoolUse remains alive through the send. It builds the existing v2 utxotx wire payload from exact family bytes, ordered transparent inputs, their proof metadata and the root captured with those proofs. It does not convert an Orchard body into a Historical transaction or read a separate root afterward.

Bridge input proof capture first copies provider coins, then proves every corresponding leaf under one forest read guard. It returns the owned root and complete proof vector together. Existing cache generations still reject invalidation during capture; cached results now also require the exact ordered input list. Historical proof generation delegates to the same capture path. The returned snapshot is not lasting selected-chain authorization. An externally owned forest without a configured guard retains its existing caller-serialization requirement.

The serializer enforces existing receiver size bounds and refuses confidential metadata because v2 cannot encode its commitment. It makes no transaction-validity, Orchard admission or readmission claim. The existing receive handler still lacks typed Orchard verification/admission; this is outbound typed proof serving only. Tests use a real isolated forest and structural body fixtures, independently verify inclusion proofs, exact wire bytes and owned-root retention, and exercise whole-result refusal. The helper runs in component tests; the daemon adapter is compiled in both configurations, not exercised through a network transport fixture. No unsafe-original or race reproduction.
