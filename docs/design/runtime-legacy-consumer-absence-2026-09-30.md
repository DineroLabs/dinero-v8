ChainstateService now refuses to install a typed runtime notification provider while any actual legacy ChainOracle, TimeOracle, TransactionOracle or extra-wallet registration is present. A disconnected socket is still a configured consumer. The existing selected-state owner serializes installation and all five registration/removal setters; non-null legacy attachment also refuses while a provider is installed. A refused update preserves both registrations and the installed provider. Explicitly removing a provider never removes legacy registrations or declares them absent.

It does not implement those adapters, install the production provider, claim pool/vault/wallet completeness or acknowledge deliveries.
