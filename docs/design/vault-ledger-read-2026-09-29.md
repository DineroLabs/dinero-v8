# Complete reads of existing vault ledger entries

FileLedgerStore loadAll now requires each existing JSON-line record to have the exact fields for its declared entry variant. Duplicate, missing, unknown, or wrong-variant fields refuse. Outpoints require both a fully decoded 32-byte hash and a uint32 integer index. Integer tokens are checked without floating/string coercion or narrowing. String escapes round-trip the writer's control bytes and support Unicode surrogate pairs; malformed escapes refuse. The reader parses the actual kind field rather than searching text inside another string.

All nine existing entry types and serialized writer bytes remain unchanged. Nullable accounts remain supported only for PolicyAdjustment. Raw string bytes from the existing writer remain preserved. Records may use different field order and legal JSON whitespace. Sequences must be strictly increasing after the first record; the actual ledger’s initial zero sequence and later gaps remain allowed. Each writer line requires its newline delimiter. Empty lines remain allowed. Missing/unavailable reads, non-EOF read errors, incomplete trailing lines, and malformed late rows throw before any vector is returned. No rewrite, default account, or partial inventory is published.

Four patched-path cases exercise the actual store, all variants, byte-for-byte read preservation, complete field sets, integer/hex/escape boundaries, incomplete final lines, sequence refusal and unavailable-path retry. Existing standalone ledger store cases remain unchanged and are separately required. No original-source control, race/deadlock reproduction, stream error injection, fsync/power-loss, multiprocess snapshot, or new ownership claim.

This legacy ledger format still lacks full deposit chain bindings and withdrawal request/state. Empty reads do not prove fresh ownership or deletion/backup completeness. The runtime's complete durable vault restoration, checked durable transition, wallet request integration, and notification provider remain separate open work. No mainnet activation or release readiness. Locally qualified.
