# Checked operator status decisions

Locally qualified. The service reads the full unsigned counter without conflating overflow with zero. Invalidate/reconsider require an available next generation before operator effects. The generation writer stages only into the caller's batch and returns explicit refusal; callers require success before committing. The invalid target and its generation now commit in one checked synchronous batch before its memory flag is published. Descendant invalidity writes are checked before publishing each corresponding memory flag. Reconsider retains its existing single batch for all cleared flags and the generation.

The existing target-before-descendants crash boundary remains after target durability. Invalidation can still leave a committed canonical-disconnect prefix or a committed target/descendant prefix on a later error. This change does not make the entire invalidation/reorg one transaction, install a notification provider, or add automatic transaction readmission. The retained intent and existing restart propagation remain required. Header-only metadata uses the existing complete-index staging path; missing data/undo-bearing metadata refuses.

Four patched-path cases use the actual ChainstateService, isolated RocksDB and an isolated header-only index graph: checked counter/staged commit and reopen, invalidation refusal and durable decision, reconsider refusal and successful joint commit, and actual header-only metadata staging versus missing data-bearing metadata refusal. No original-source, race, synchronization-removal, or exploit control is run. Existing fixture assertions and crash boundaries remain. ON/OFF/full graph, actual lifecycle checks and project sanitizer qualification are required before publication.
