# Orchard request completion and submission

`wallet.orchard.finishspend` takes the same six named fields as `wallet.orchard.queuespend`. It requires the exact original request. The original revision remains accepted on a retry; completion never creates a reservation. Unknown and archived IDs refuse.

The selected replay source is captured before wallet SQLite/key ownership. One checked FULL read transaction authenticates the complete catalog, current account, persistent wallet identity, manager instance, live session, exact ordered recipient/memo/script/amount/fee commitment, and owned executor job. Missing jobs cannot regenerate a Reserved operation. No proof supplied by an RPC caller is accepted.

Outside wallet SQLite/key ownership, the actual ChainstateService validates the candidate against its selected live, persisted and validated parent, headers, consensus journal, active profile, pool state, anchors and nullifiers. This reuses the checked selected-pool context and verifies actual cryptographic authorizations and resources. Pure Orchard funding only: transparent inputs refuse. Verification currently holds the selected lock as the existing admission implementation does; proving and waiting do not run under that lock.

The existing finalization owner reauthenticates the catalog/current reservation and exact captured proof, commits Ready bytes with checked COMMIT, then retires only the exact executor result. Only afterward does the actual configured MempoolService receive `SubmitBody(..., WALLET)`. Its lifetime-owned pool admission reacquires current selected state and checks pending conflicts, resources and fee policy. Its existing callback requests relay after admission locks are released. A wallet switch after the durable handoff cannot replace the captured signed transaction.

Submission refusal retains Ready and returns separate `admitted`, `already_in_mempool`, submission code/message and transaction ID. A duplicate is reported separately, not as newly validated admission. A lost response or exception can retry identical stored bytes, including after wallet reopen, without generating a new proof. Accepted admission does not establish peer receipt or block inclusion. Recovered missing jobs, transparent-input shielding, cancellation, bounded shutdown, whole-node restart/reorg/load and release readiness remain separate work.
