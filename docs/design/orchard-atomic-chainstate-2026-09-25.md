# Orchard staged atomic chainstate

This is a stateful integration component, not enabled block admission.

`StageOrchardChainstateConnectUnderLock` resolves coins, authorizes both transaction families, prepares the Orchard transition and computes the mixed forest transition. It stages net UTXOs, conventional undo, Orchard frontier/pool/nullifier/anchor state and undo, the existing UD forest delta, a forest marker, the active height index, storage tip, validated tip, exact encoded block body and active transaction indexes into one initially empty ChainDB batch. Optional forest checkpoints and their checksums use that same batch. Nothing commits or mutates the caller's forest.

Parent storage/validated tips, height index, forest marker, selected header bytes, heights and cumulative work must agree before staging. Header records must already be persisted by the header path. Their existence is not proof of contextual header validity: the eventual connector must supply authenticated selected headers and complete difficulty/PoW, time, resource checks before committing. The peer proof and its ordered spent-output metadata are checked against the same resolved coins and full parent forest before any outer commit. The computed forest root must match the exact candidate header. A retained delta or conventional undo must match byte-for-byte on reconnect.

The disconnect adapter reads the durable delta, checks it against the current forest and both selected header roots, and returns a private restored forest. No pre-restart prepared object is required. It stages coin and Orchard reversal, parent tip/marker restoration, and removal of the disconnected height index and checkpoint together. Header/body/undo/delta records remain available for reconnect. Corrupt local data produces a storage error; a candidate header with the wrong computed root is a body rejection.

Every failure rolls back the entire caller batch, including failures after coin/state preparation. Publishing the returned forest before a successful single outer commit violates the API contract. Service/flatfile indexes and in-memory bookkeeping still belong to the outer connector. The versioned Orchard commit record now shares this batch. The typed body is stored byte-exactly in the existing blocks column family, with the same transaction ordinal convention used by the host index. The legacy Block reader remains unchanged. A typed stored read checks key/header identity, transaction and witness commitments and bounds; it does not establish full replay validity. An existing transaction location is refused on connect rather than overwritten without undo. Disconnect verifies exact index ownership before removal and retains the body. Reconnect may replace corrupt local body bytes only as part of preparing the full state transition.

## Verification

Generated RocksDB fixtures use canonical hex-encoded Coin scripts and honest synthetic Orchard proofs plus a signed ordinary child. Tests cover abandoned connect/disconnect batches, late retained-delta failure, inconsistent local markers/forest, committed close/reopen, production checkpoint-plus-delta forest restore, persistent-delta undo, exact parent restoration and reconnect. Stored bodies reopen byte-exactly; truncated and parseable wrong-Merkle bodies fail the typed reader. Reconnect replaces corrupt local bytes in the same batch as state and indexes. Both checkpoint-enabled and delta-only modes run. Corrupt delta shape/hash/count and duplicate deletion records fail without mutating the source forest.

## Commit record and startup consistency

The staged stateful path writes `orchard_consensus_journal:v1:<height_be_hex>:<block_hash_hex>` in the same batch before the tip markers. It is distinct from the historical shielded journal: the old fingerprint describes different state. Its exact value is `DOC1` followed by SHA-256 of the `DIN/orchard/chainstate-commit/v1` domain, network/genesis/branch and activation context, height, the 128-byte selected header, 64-character chainwork hex, forest leaf count, pool balance, Orchard tree size/anchor and length-prefixed canonical frontier. Integer fields are fixed-width little endian (network 1, branch/activation/height/frontier length 4, counts/balance 8). Header identity binds the selected transparent forest root. The record is local persistence metadata, not a new wire commitment or an independent proof of chain validity.

At the first Orchard block there is no predecessor Orchard state. Later connects require the selected parent's record to match its state and forest. Disconnect checks the current record and the restored parent's retained record, including the parent state decoded from exact-tip undo. A retained record survives disconnect just like a retained header; its existence alone never makes a block active. Reconnect must reproduce it exactly.

`AuditOrchardChainstateTipUnderLock` reads/authenticates the stored body and prepares—but never commits—its reversal. It checks the tip/height/header/forest markers and record, frontier, current-tip coin and index ownership, current-tip nullifier owners/anchor references, conventional/Orchard undo, forest delta and restored parent record. Failure leaves state untouched and reports local corruption; it never tries to repair a mismatch by rewinding only a tip pointer. The caller must first restore the forest against authenticated selected headers and hold the same writer lock. This does not scan every historical coin or nullifier and does not replace genesis replay, cryptographic validation or a global database-integrity audit.

## Process-exit boundaries

The separately registered `OrchardAtomicCrash` test spawns fresh child processes, avoiding inherited RocksDB/Rayon worker state. On generated temporary stores only, children exit without destructors immediately before commit or immediately after synchronous `writeBatch` returns. A fresh process reopens the store. Connect and disconnect each run in checkpoint and delta-only modes: eight abrupt-exit cases. Every persisted row/key must equal the independently committed old or new state. Only the tip's final four-byte wall-clock diagnostic timestamp is compared separately (shape and recency); all consensus bytes remain in the exact comparison. Production `RestoreHistoricalForest` and the tip audit then check recovery. A post-activation continuation also exercises parent-record checks in both directions. Missing/corrupt records and changed network-branch/activation contexts fail without state mutation.

These are isolated process/database tests, not a running daemon, hardware power-loss, reindex, stateless-node, wallet, activation or release qualification. The daemon still needs to invoke the startup audit and perform durable-commit-before-memory-publication through its live service. Mainnet activation remains unset.
