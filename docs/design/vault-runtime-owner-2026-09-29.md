# Vault runtime ownership and canonical deposit reads

Locally qualified.

RPC handlers now retain the same shared VaultService from acquisition through the full handler. Runtime shutdown detaches future acquisitions; a call already holding an owner keeps its instance alive and cannot be redirected to a replacement. A single runtime getter replaces the independent raw RPC registry pointer. Tip notifications and wallet-output observation retain a service; observation copies the operator script/account together under the runtime mutex. Wallet float lookup retains an actual WalletUse.

Deposit verification requires the caller's exact service owner, captures the configured operator script under the runtime mutex, releases that mutex, then holds the actual chainstate index lifetime and selected lock through persisted unspent-coin and canonical typed-body inclusion reads. It decodes the established hexadecimal coin-script representation with explicit ASCII validation before comparing exact operator bytes. Unavailable source, mismatched operator script, missing inclusion or a replaced runtime refuses without publishing output parameters. The actual vault.observe handler uses the retained service and the checked values.

Four patched-path cases (two backend-OFF) cover real runtime initialization/detach/replacement, retained instance and actual metrics RPC acquisition, operator binding rejection, real historical archive/coin verification and actual observation RPC, then real shield spending that coin and verification of its typed transparent change, unavailable-store retry, stopped source and old-owner refusal. No unsafe-original, race, deadlock, bypass or synchronization-removal control is used.

This is operation lifetime and an as-of canonical deposit observation. It does not drain shutdown, make multi-field metrics atomic, implement vault ledger persistence/replay, prove all credit/withdrawal transitions atomic, or install the production notification provider. Runtime persistence remains an existing incomplete path; in-flight operations may finish against their retained instance after detach. Network activation, whole-node/platform/load and release qualification remain open.

Shutdown detaches the global service under the runtime mutex and destroys its local callback owner after releasing that mutex. Existing retained callers may still finish. The daemon shutdown integration inherited from the parent stops services before this detach. This is not a durable completion or general drain guarantee.

Before qualification, the canonical output observation was extended to carry the exact transparent amount and script from the same historical or typed body read. VerifyOperatorDeposit requires both to match the persisted unspent coin. Confidential historical outputs have no transparent amount; absent outputs have neither amount nor script. Existing positive historical/typed fixture cases exercise exact field capture, comparison refusals and output absence. No original-source corruption or exploit reproduction is used. This binds recorded coin fields to one canonical body, without certifying independent historical validation, backup completeness or ongoing operator authorization.
