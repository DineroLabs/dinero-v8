# Owned relay refresh requests and prepared tip updates

Relay operations snapshot their configured callbacks under a dedicated mutex; setters exchange the callable and destroy the replaced owner after releasing it. Calls execute outside relay state/configuration locks. CSN mode reads use an atomic value. Other non-owning logger/orphan-pool lifetime and initialization contracts remain unchanged.

Proof refresh precomputes a bounded outbound batch and its pending reservations before publishing tracking. Each reservation owns a unique batch token. Callback completion may erase it without a later write recreating it. A tip clear or replacement causes subsequent unsent items from the old batch to be skipped. On callback exception, the attempted send remains ambiguous/pending; only this batch's unattempted reservations are released. Request limits, timeout, cooldown and peer rotation remain. Checks describe an as-of reservation; concurrent tip changes can occur after the check, and a request is not proof validation or network delivery acknowledgment.

PrepareTipChanged retains the refresh lock in a thread-affine object. Abandon preserves prior tracking; PublishAfterCommit only swaps tracking and unlocks, with no callback/logger or allocation. Existing OnTipChanged uses it. The relay must outlive its prepared object, and callers must not reenter while holding it. This is one real consumer prerequisite, not a complete production notification provider, durable relay/readmission, Orchard support, all-consumer readiness or release qualification. Mainnet remains unset.
