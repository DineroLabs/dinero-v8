# Chain-independent Orchard account ownership metadata

The shared transparent reservation work needs to read authenticated account ownership without creating a scan at an invented origin. Account recovery currently decodes this metadata while constructing an initial scanner, including when it only wants the delivery locator.

`OrchardAccountMetadata` now owns the existing DNORAC01–06 metadata decoder. It checks the same domain, viewing-key identity, address counters, ordered observations, archive/delivery/parent bindings, operation encoding and terminal EOF. Reserved transparent inputs and exact signed Ready bodies are retained. It neither changes serialized bytes nor restores a scanner. Full account restoration and rescan use this same decoder, then retain their original scan restoration/reset and selected observation checks. The delivery locator reader uses the metadata result directly; existing source-origin acquisition and subsequent full restore checks are retained.

The decoder requires the caller to authenticate its bytes through `WalletSnapshotStore` under the existing seed and SQLite owner. It is not an AEAD verifier, complete catalog, selected-chain observation certificate, spendability check or reservation release authority. Returned metadata owns its queue and contains no borrowed decrypted scan span. The metadata library links the operation/storage/typed transaction boundary, without adding the account scan or daemon service as a direct dependency.

The real account fixture now checks exact Reserved/Ready queue bytes and reopened authenticated envelopes, refusal of wrong domains/keys/framing/parent bindings, and legacy ownership layouts.
