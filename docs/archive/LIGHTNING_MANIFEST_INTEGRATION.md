# ⚡ Lightning Vendor Integrity Manifest - Integration Guide

**Status:** Production-ready audit and compliance system ✅

---

## 🎯 **Purpose**

The Lightning Vendor Integrity Manifest provides **cryptographic provenance** and **runtime transparency** for all vendored Lightning Network dependencies in DineroCoin.

**Key Features:**
- ✅ Cryptographic verification (SHA256 checksums)
- ✅ Audit trail with timestamps and git commits
- ✅ Runtime RPC queries (`getlightninginfo`)
- ✅ Compile-time feature detection
- ✅ BOLT spec compliance mapping
- ✅ Supply chain transparency
- ✅ Auto-generated from build artifacts

## 🚀 **Integration Steps**

### Step 1: Add to CMake Build

Edit `src/CMakeLists.txt`:

```cmake
# Add Lightning manifest sources
add_library(lightning_manifest STATIC
    lightning_manifest.cpp
)

target_include_directories(lightning_manifest PUBLIC
    ${CMAKE_CURRENT_SOURCE_DIR}
)

# Link into main daemon
target_link_libraries(dinerod PRIVATE
    lightning_manifest
    lightning_core_static
)
```

### Step 2: Implement RPC Command

Create `src/rpc/lightning.cpp`:

```cpp
#include "lightning_manifest.h"
#include "rpc/server.h"
#include "univalue.h"

static RPCHelpMan getlightninginfo()
{
    return RPCHelpMan{"getlightninginfo",
        "\nReturns Lightning Network library information and BOLT compliance status.\n",
        {},
        RPCResult{
            RPCResult::Type::OBJ, "", "",
            {
                {RPCResult::Type::STR, "manifest_version", "Manifest format version"},
                {RPCResult::Type::ARR, "libraries", "Vendored Lightning libraries",
                    {
                        {RPCResult::Type::OBJ, "", "",
                            {
                                {RPCResult::Type::STR, "name", "Library name"},
                                {RPCResult::Type::STR, "version", "Library version"},
                                {RPCResult::Type::STR, "sha256", "SHA256 checksum"},
                                {RPCResult::Type::STR, "verification", "Verification status"},
                            }
                        },
                    }
                },
                {RPCResult::Type::OBJ, "bolt_compliance", "BOLT spec support status"},
            }
        },
        RPCExamples{
            HelpExampleCli("getlightninginfo", "")
            + HelpExampleRpc("getlightninginfo", "")
        },
        [&](const RPCHelpMan& self, const JSONRPCRequest& request) -> UniValue
        {
            // Get manifest JSON
            std::string json_str = lightning::GetLightningInfoJSON();

            // Parse and return as UniValue
            UniValue result(UniValue::VOBJ);
            result.read(json_str);
            return result;
        },
    };
}

void RegisterLightningRPCCommands(CRPCTable &t)
{
    static const CRPCCommand commands[] = {
        { "lightning", &getlightninginfo },
    };
    for (const auto& c : commands) {
        t.appendCommand(c.name, &c);
    }
}
```

### Step 3: Register RPC Command

Edit `src/rpc/register.h`:

```cpp
void RegisterLightningRPCCommands(CRPCTable &t);
```

Edit `src/rpc/server.cpp`:

```cpp
void RegisterAllCoreRPCCommands(CRPCTable &t)
{
    RegisterBlockchainRPCCommands(t);
    RegisterNetRPCCommands(t);
    RegisterMiscRPCCommands(t);

```

### Step 4: Log Manifest on Startup

Edit `src/init.cpp`:

```cpp
#include "lightning_manifest.h"

bool AppInitMain(const util::Ref& context)
{

    // ... continue initialization ...
}
```

## 🔒 **Security Considerations**

### 1. Tamper Detection

The manifest includes SHA256 checksums for **every library**:

```bash
# If a library is modified, verification will fail
$ ./scripts/verify-lightning-checksums.sh
❌ libwally-core - SHA256 MISMATCH
   Expected: 1d517946de536afb...
   Actual:   deadbeef12345678...
```

### 2. Audit Trail

Every library includes:
- Git commit hash
- Build timestamp
- Compiler version
- SHA256 checksum

This enables **reproducible builds** and **forensic analysis**.

### 3. Runtime Verification

On startup, DineroCoin can verify checksums:

```cpp
if (!lightning::VerifyLightningChecksums()) {
    return InitError(_("Lightning libraries corrupted!"));
}
```

### 4. RPC Transparency

Any user can query library integrity:

```bash
dinero-cli getlightninginfo | jq '.libraries[] | {name, sha256, verification}'
```

## 📋 **CI/CD Integration**

Add to `.github/workflows/build.yml`:

```yaml
- name: Generate Lightning Manifest
  run: |
    ./scripts/vendor-libwally.sh
    ./scripts/vendor-secp256k1-zkp.sh
    ./scripts/vendor-blake3.sh
    ./scripts/generate-lightning-manifest.sh

- name: Verify Lightning Checksums
  run: |
    ./scripts/verify-lightning-checksums.sh
    if [ $? -ne 0 ]; then
      echo "❌ Lightning checksums failed!"
      exit 1
    fi

- name: Archive Manifest
  uses: actions/upload-artifact@v3
  with:
    name: lightning-manifest
    path: LIGHTNING_MANIFEST.json

- name: Commit Manifest (on release)
  if: startsWith(github.ref, 'refs/tags/')
  run: |
    git config user.name "DineroCoin Bot"
    git config user.email "bot@dinero-coin.com"
    git add LIGHTNING_MANIFEST.json
    git commit -m "chore: update Lightning manifest for ${{ github.ref_name }}"
    git push
```

## 🎓 **Best Practices**

### 1. Update Manifest After Library Changes

```bash
# After building/updating any Lightning library:
./scripts/vendor-libwally.sh        # Build library
./scripts/generate-lightning-manifest.sh  # Update manifest
git add LIGHTNING_MANIFEST.json
git commit -m "build: update Lightning manifest after libwally rebuild"
```

### 2. Embed Manifest in Release Binaries

Option A: **Compile into binary**

Already done! The C++ implementation embeds checksums as `constexpr`.

Option B: **Bundle JSON file**

```bash
# Include manifest in release archive
tar -czf dinerocoin-0.1.0-lightning.tar.gz \
    dinerod dinero-cli dinero-qt \
    LIGHTNING_MANIFEST.json \
    LIGHTNING_INSTALLATION_COMPLETE.md
```

### 3. Sign Manifest for Official Releases

```bash
# GPG sign the manifest
gpg --detach-sign --armor LIGHTNING_MANIFEST.json
# Creates: LIGHTNING_MANIFEST.json.asc

# Users can verify:
gpg --verify LIGHTNING_MANIFEST.json.asc LIGHTNING_MANIFEST.json
```

## 📊 **Use Cases**

Auditors can verify:
- All dependencies are pinned to specific commits
- SHA256 checksums match expected values
- BOLT spec compliance is documented
- No unexpected libraries are linked

**Query via RPC:**
```bash
dinero-cli getlightninginfo | jq -r '.libraries[] | "\(.name): \(.sha256)"'
```

Check which BOLT specs are supported:

```bash
dinero-cli getlightninginfo | jq '.bolt_compliance'
```

## 🔧 **Maintenance**

### Regular Updates

1. **After vendoring new library:**
   ```bash
   ./scripts/vendor-libwally.sh  # Update library
   ./scripts/generate-lightning-manifest.sh  # Regenerate manifest
   git add LIGHTNING_MANIFEST.json
   git commit -m "build: update manifest after libwally upgrade"
   ```

2. **Before each release:**
   ```bash
   # Verify all checksums
   ./scripts/verify-lightning-checksums.sh

   # Regenerate manifest with fresh timestamps
   ./scripts/generate-lightning-manifest.sh

   # Review changes
   git diff LIGHTNING_MANIFEST.json
   ```

3. **Periodic audits:**
   ```bash
   # Compare runtime checksums with manifest
   dinero-cli getlightninginfo | jq '.libraries[] | {name, sha256}' > runtime.json
   jq '.libraries[] | {name, sha256: .binary.sha256}' LIGHTNING_MANIFEST.json > manifest.json
   diff runtime.json manifest.json
   ```
