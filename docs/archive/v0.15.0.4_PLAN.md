## 🎯 The Goal

**Enable ChainManager to automatically switch to the chain with the most cumulative work.**

**Current State** (v0.15.0.3):
- ✅ BlockIndex DAG exists
- ✅ Chainwork tracked
- ✅ Candidate tips known
- ❌ No automatic activation

**Target State** (v0.15.0.4):

- ✅ Crash-safe rollback on failure

## 🔒 Critical Invariants (Non-Negotiable)

These invariants MUST hold before, during, and after every reorg:

### INVARIANT 1: Single Reorg Entry Point
```
✅ ONLY ChainManager::ActivateBestChain() may trigger reorgs
❌ NEVER trigger reorgs from:
   - Block acceptance (BlockAcceptor::ConnectBlock)
   - Block validation
   - Network message handlers
   - RPC handlers (except explicit invalidateblock)
   - Wallet code
   - Mining code
```

**Why**: Prevents race conditions, ensures atomic state transitions.

---

### INVARIANT 2: Atomicity (All-or-Nothing)
```
A reorg either:
  ✅ Completes fully (all disconnects + all connects succeed)
  OR
  ✅ Rolls back completely (restores original chain state)

❌ NEVER leave chain in intermediate state:
   - Partially disconnected
   - Partially connected
   - Mixed UTXO state
   - Orphaned tip
```

**Implementation**:
```cpp
bool ChainManager::PerformReorg(CBlockIndex* new_tip) {
    CBlockIndex* rollback_point = active_tip_;  // Save for rollback

    // Phase 1: Disconnect old chain
    if (!DisconnectToFork(fork_point)) {
        // Rollback: reconnect to original tip
        ReconnectToOriginalTip(rollback_point);
        return false;
    }

    // Phase 2: Connect new chain
    if (!ConnectToNewTip(new_tip)) {
        // Rollback: reconnect to original tip
        ReconnectToOriginalTip(rollback_point);
        return false;
    }

    // Success: commit new tip
    active_tip_ = new_tip;
    return true;
}
```

### INVARIANT 3: Undo Data Verification
```
Before disconnecting block N:
  ✅ Verify undo record exists for block N
  ✅ Verify undo record deserializes correctly
  ✅ Verify undo record matches block transactions

If any verification fails:
  ❌ ABORT reorg
  ❌ DO NOT disconnect block
  ✅ Return to original chain
```

**Implementation**:
```cpp
bool ChainManager::DisconnectBlock(CBlockIndex* block_index) {
    // CRITICAL: Verify undo data BEFORE mutating state
    auto undo_result = chain_db_->getUndo(block_index->hash);
    if (!undo_result.ok()) {
        LOG_ERROR("REORG ABORT: Missing undo data for block " + block_index->hash);
        return false;  // Triggers rollback
    }

    UndoRecord undo = undo_result.value();

    // Verify undo record matches block
    if (!ValidateUndoRecord(undo, block_index)) {
        LOG_ERROR("REORG ABORT: Corrupt undo data for block " + block_index->hash);
        return false;  // Triggers rollback
    }

    // Safe to proceed: delegate to BlockAcceptor
    return BlockAcceptor::DisconnectBlock(...);
}
```

### INVARIANT 4: Reorg Depth Limits
```
Regtest:  No limit (allow deep reorgs for testing)
Testnet:  100 blocks (warn at 30)
Mainnet:  30 blocks (hard limit, enter safe mode)

Beyond limit:
  ❌ REJECT automatic reorg
  ✅ Log critical warning
  ✅ Enter safe mode
  ✅ Require manual intervention
```

**Rationale**: Deep reorgs (>30 blocks) indicate:
- 51% attack
- Network partition
- Node isolation
- Time warp attack

**Implementation**:
```cpp
bool ChainManager::PerformReorg(CBlockIndex* new_tip) {
    int reorg_depth = CountDisconnectBlocks(active_tip_, fork_point);

    // Apply network-specific limits
    const auto& params = dinero::Params();
    int max_depth = params.maxReorgDepth;  // 30 for mainnet, 100 for testnet, 0 for regtest

    if (max_depth > 0 && reorg_depth > max_depth) {
        LOG_ERROR("REORG REJECTED: Depth " + std::to_string(reorg_depth) +
                  " exceeds limit " + std::to_string(max_depth));
        EnterSafeMode("Deep reorg attempt blocked");
        return false;
    }

    // Proceed with reorg...
}
```

### INVARIANT 5: ChainDB Write Token Preservation
```
✅ ONLY BlockAcceptor may create ChainWriteToken
✅ ChainManager delegates to BlockAcceptor for UTXO mutations
❌ ChainManager NEVER touches ChainDB directly

Pattern:
  ChainManager::DisconnectBlock()
    ↓ delegates to
  BlockAcceptor::DisconnectBlock()
    ↓ creates ChainWriteToken
  ChainDB::putCoin() / deleteCoin()
```

**Why**: Preserves compile-time write authorization model.

### INVARIANT 6: Mempool Reconciliation
```
After successful reorg:
  ✅ Resurrect transactions from disconnected blocks (if not in new chain)
  ✅ Evict transactions now invalid due to spent inputs
  ✅ Re-validate mempool against new UTXO set
  ✅ Update descendant/ancestor tracking

Order matters:
  1. Disconnect old chain (save txs)
  2. Connect new chain
  3. Reconcile mempool
  4. Notify wallets
```

**Implementation**:
```cpp
void ChainManager::ReconcileMempoolAfterReorg(
    const std::vector<CBlockIndex*>& disconnected,
    const std::vector<CBlockIndex*>& connected) {

    if (!mempool_) return;

    // Step 1: Collect transactions from disconnected blocks
    std::vector<Transaction> resurrected;
    for (auto* block_idx : disconnected) {
        Block block = ReadBlockFromDisk(block_idx);
        for (const auto& tx : block.vtx) {
            if (!tx.IsCoinbase()) {
                resurrected.push_back(tx);
            }
        }
    }

    // Step 2: Remove transactions now in connected blocks
    for (auto* block_idx : connected) {
        Block block = ReadBlockFromDisk(block_idx);
        for (const auto& tx : block.vtx) {
            auto it = std::find_if(resurrected.begin(), resurrected.end(),
                [&tx](const Transaction& t) { return t.GetTxid() == tx.GetTxid(); });
            if (it != resurrected.end()) {
                resurrected.erase(it);
            }
        }
    }

    // Step 3: Re-add valid transactions to mempool
    for (const auto& tx : resurrected) {
        std::string error;
        mempool_->AcceptTransaction(tx, error);  // May fail (spent inputs)
    }
}
```

## 🧭 Single Reorg Entry Point

**Designated Entry Point**: `ChainManager::ActivateBestChain()`

**Call Sites** (exhaustive list):
1. ✅ `BlockAcceptor::AcceptBlockFromRPC()` - After successful block acceptance (v0.15.0.2)
2. ✅ `BlockAcceptor::AcceptBlockFromPeer()` - After P2P block acceptance (future)
3. ❌ Nowhere else

**Execution Flow**:
```
Block Accepted
    ↓
BlockAcceptor::ConnectBlock()
    ├─ Validate block
    ├─ Apply UTXO changes
    ├─ Populate BlockIndex (v0.15.0.3)
    └─ Return success
    ↓
ChainManager::ActivateBestChain()  ← SINGLE ENTRY POINT
    ├─ GetBestCandidate()
    ├─ Compare chainwork
    └─ IF (new_tip.chainwork > active_tip.chainwork)
           PerformReorg(new_tip)
```

**What Does NOT Trigger Reorgs**:
- ❌ Mining new blocks (just extends active chain)
- ❌ Wallet rescans
- ❌ RPC queries
- ❌ Network sync (only after block acceptance)
- ❌ Daemon startup (reads persisted tip)

## 🔄 Reorg Execution Phases

### Phase 1: Decision (No State Mutation)
```cpp
bool ChainManager::ActivateBestChain() {
    CBlockIndex* best_candidate = GetBestCandidate();

    if (!best_candidate) {
        return true;  // No candidates, nothing to do
    }

    if (best_candidate == active_tip_) {
        return true;  // Already on best chain
    }

    // Compare chainwork
    if (chainwork::CompareWork(best_candidate->chainwork, active_tip_->chainwork) <= 0) {
        return true;  // Current chain has equal or more work
    }

    // New chain has more work - proceed with reorg
    return PerformReorg(best_candidate);
}
```

### Phase 2: Planning (No State Mutation)
```cpp
bool ChainManager::PerformReorg(CBlockIndex* new_tip) {
    // Find fork point (lowest common ancestor)
    CBlockIndex* fork_point = FindFork(active_tip_, new_tip);

    if (!fork_point) {
        LOG_ERROR("REORG ABORT: Cannot find fork point");
        return false;
    }

    // Build disconnect path (active_tip → fork_point)
    std::vector<CBlockIndex*> disconnect_path = GetDisconnectPath(active_tip_, fork_point);

    // Build connect path (fork_point → new_tip)
    std::vector<CBlockIndex*> connect_path = GetConnectPath(fork_point, new_tip);

    // Check reorg depth limit
    if (disconnect_path.size() > maxReorgDepth) {
        LOG_ERROR("REORG ABORT: Depth exceeds limit");
        EnterSafeMode("Deep reorg blocked");
        return false;
    }

    // Verify undo data exists for ALL disconnect blocks
    for (auto* block_idx : disconnect_path) {
        if (!chain_db_->getUndo(block_idx->hash).ok()) {
            LOG_ERROR("REORG ABORT: Missing undo for block " + block_idx->hash);
            return false;
        }
    }

    // All checks passed - proceed to execution
    return ExecuteReorg(disconnect_path, connect_path);
}
```

### Phase 3: Execution (Atomic State Transition)
```cpp
bool ChainManager::ExecuteReorg(
    const std::vector<CBlockIndex*>& disconnect_path,
    const std::vector<CBlockIndex*>& connect_path) {

    // Save original tip for rollback
    CBlockIndex* rollback_point = active_tip_;

    LOG_INFO("REORG: Disconnecting " + std::to_string(disconnect_path.size()) + " blocks");

    // Step 1: Disconnect old chain (reverse order)
    for (auto it = disconnect_path.rbegin(); it != disconnect_path.rend(); ++it) {
        CBlockIndex* block_idx = *it;

        Block block = ReadBlockFromDisk(block_idx);
        std::string error;

        if (!BlockAcceptor::DisconnectBlock(block, block_idx->height, error)) {
            LOG_ERROR("REORG FAILED: DisconnectBlock failed: " + error);
            // CRITICAL: Rollback to original chain
            return RollbackToOriginalChain(rollback_point);
        }

        LOG_INFO("  Disconnected block " + std::to_string(block_idx->height) +
                 ": " + block_idx->hash.substr(0, 16) + "...");
    }

    LOG_INFO("REORG: Connecting " + std::to_string(connect_path.size()) + " blocks");

    // Step 2: Connect new chain (forward order)
    for (auto* block_idx : connect_path) {
        Block block = ReadBlockFromDisk(block_idx);
        std::string error;

        if (!BlockAcceptor::ConnectBlock(block, block_idx->height,
                                         block_idx->pprev->chainwork, error)) {
            LOG_ERROR("REORG FAILED: ConnectBlock failed: " + error);
            // CRITICAL: Rollback to original chain
            return RollbackToOriginalChain(rollback_point);
        }

        LOG_INFO("  Connected block " + std::to_string(block_idx->height) +
                 ": " + block_idx->hash.substr(0, 16) + "...");
    }

    // Step 3: Update active tip
    active_tip_ = connect_path.back();

    // Step 4: Reconcile mempool
    ReconcileMempoolAfterReorg(disconnect_path, connect_path);

    // Step 5: Notify subsystems
    NotifyReorgComplete(disconnect_path, connect_path);

    LOG_INFO("REORG SUCCESS: New tip at height " + std::to_string(active_tip_->height) +
             ": " + active_tip_->hash.substr(0, 16) + "...");

    return true;
}
```

### Phase 4: Rollback on Failure (Crash Safety)
```cpp
bool ChainManager::RollbackToOriginalChain(CBlockIndex* original_tip) {
    LOG_ERROR("REORG ROLLBACK: Attempting to restore original chain");

    // Find current state
    auto current_tip_result = chain_db_->getTip();
    if (!current_tip_result.ok()) {
        LOG_ERROR("CRITICAL: Cannot determine current tip during rollback");
        EnterSafeMode("Reorg rollback failed - manual recovery required");
        return false;
    }

    std::string current_tip_hash = current_tip_result.value().hash;
    CBlockIndex* current_tip = FindBlockIndex(current_tip_hash);

    if (!current_tip) {
        LOG_ERROR("CRITICAL: Current tip not in BlockIndex");
        EnterSafeMode("Reorg rollback failed - manual recovery required");
        return false;
    }

    // Find fork between current state and original tip
    CBlockIndex* fork = FindFork(current_tip, original_tip);

    // Disconnect blocks to fork
    std::vector<CBlockIndex*> rollback_disconnect = GetDisconnectPath(current_tip, fork);
    for (auto it = rollback_disconnect.rbegin(); it != rollback_disconnect.rend(); ++it) {
        Block block = ReadBlockFromDisk(*it);
        std::string error;

        if (!BlockAcceptor::DisconnectBlock(block, (*it)->height, error)) {
            LOG_ERROR("CRITICAL: Rollback disconnect failed: " + error);
            EnterSafeMode("Reorg rollback failed - manual recovery required");
            return false;
        }
    }

    // Reconnect to original tip
    std::vector<CBlockIndex*> rollback_connect = GetConnectPath(fork, original_tip);
    for (auto* block_idx : rollback_connect) {
        Block block = ReadBlockFromDisk(block_idx);
        std::string error;

        if (!BlockAcceptor::ConnectBlock(block, block_idx->height,
                                         block_idx->pprev->chainwork, error)) {
            LOG_ERROR("CRITICAL: Rollback reconnect failed: " + error);
            EnterSafeMode("Reorg rollback failed - manual recovery required");
            return false;
        }
    }

    // Restore original tip
    active_tip_ = original_tip;

    LOG_INFO("REORG ROLLBACK SUCCESS: Restored original tip");
    return true;
}
```

## 🚨 Failure Modes and Mitigations

### Failure Mode 1: Missing Undo Data
**Symptom**: Cannot disconnect block during reorg
**Mitigation**: Pre-verify undo data exists before starting reorg
**Rollback**: Return to original chain state

---

### Failure Mode 2: Corrupt Undo Data
**Symptom**: Undo deserialization fails or doesn't match block
**Mitigation**: Validate undo record matches block transactions
**Rollback**: Return to original chain state

---

### Failure Mode 3: UTXO Missing During Reconnect
**Symptom**: ConnectBlock fails because input UTXO doesn't exist
**Mitigation**: This indicates database corruption or invalid block
**Rollback**: Return to original chain state, enter safe mode

---

### Failure Mode 4: Rollback Failure
**Symptom**: Cannot restore original chain after failed reorg
**Mitigation**: Enter safe mode, require manual recovery
**Recovery**: Restart node, re-sync from trusted peer

---

### Failure Mode 5: Crash Mid-Reorg
**Symptom**: Daemon crashes during disconnect/connect phase
**Mitigation**: On restart, ChainDB tip points to last committed block
**Recovery**: Rebuild BlockIndex from headers, validate against ChainDB tip

## 🧠 Key Design Decisions

### Decision 1: When to Trigger ActivateBestChain()
**Option A**: After every block acceptance ✅ CHOSEN
**Option B**: Periodic timer (every 10 seconds)
**Option C**: On-demand (RPC trigger only)

**Rationale**: Option A ensures immediate fork resolution, matches Bitcoin Core behavior.

---

### Decision 2: Reorg Depth Limits
**Regtest**: 0 (no limit) - Allow deep reorgs for testing ✅
**Testnet**: 100 blocks (warn at 30) ✅
**Mainnet**: 30 blocks (hard limit) ✅

**Rationale**: 30 blocks ≈ 5 hours (at 10 min/block). Beyond this indicates attack or network partition.

---

### Decision 3: Mempool Reconciliation Timing
**Option A**: During reorg (before tip update)
**Option B**: After reorg (after tip update) ✅ CHOSEN

**Rationale**: Mempool should only contain transactions valid against active chain. Must reconcile after chain switch is committed.

---

### Decision 4: Rollback Strategy
**Option A**: Manual recovery only
**Option B**: Automatic rollback on any failure ✅ CHOSEN
**Option C**: Partial rollback (disconnect only)

**Rationale**: Automatic rollback preserves chain consistency. Manual recovery required only for catastrophic failures.

## 🔐 Security Considerations

### Attack Vector 1: Reorg Spam
**Threat**: Attacker mines competing forks to trigger excessive reorgs
**Mitigation**: Depth limit (30 blocks), peer banning for invalid blocks

---

### Attack Vector 2: Time Warp
**Threat**: Manipulated timestamps to create false chainwork
**Mitigation**: Already mitigated by PoW validation (blocks must meet difficulty target)

---

### Attack Vector 3: Undo Corruption
**Threat**: Attacker corrupts undo data to prevent rollback
**Mitigation**: Undo verification before reorg, safe mode on corruption
