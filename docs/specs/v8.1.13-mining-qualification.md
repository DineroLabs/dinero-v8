## Combined tests

`CompactTimingLifecycle123`, `124` and `125` keep compact activation at 124
and put timing activation immediately before, at and after it. Each exercises:

- Actual shield, transfer and unshield; exact compact bytes and independent
  txid/witness reconstruction using the existing oracle.
- Full and stateless peer convergence and locked-wallet recognition.
- A proof of the unshield output, its signed transparent child spend, removal
  of the spent leaf, disconnection/reconnection, restarts and full reindex.
- A reorg below compact activation, exclusion of now-ineligible compact work
  and descendants, then restoration of the original state.

`CompactTimingExternalMining` uses the supported `getblocktemplate/submitblock`
and `mining.getjob/mining.submit` interfaces. It mines compact shield/unshield
transactions across timing activation, checks the initial 100 DIN reward plus
selected fees, exact persisted transaction bytes, DNRS and restart consistency.
The dormant control remains. This covers daemon-owned external work assembly;
it is not a substitute for testing each distributed GUI or mobile miner binary.

All four new tests are assigned to `compact-regtest.yml`, with the existing
execution-coverage meta-check. No manual-only baseline exemption is added.

## Local evidence, 2026-09-17

Release build on macOS arm64 with `DINERO_ENABLE_COMPACT_REGTEST=ON`:

- All three timing/compact ordering lifecycles passed.
- SixtySecondConsensus, the independent ASERT oracle and SixtySecondActivation
  passed on the combined daemon.
- Both external mining interfaces mined compact-bearing blocks; the coordinator
  result retained the same shielded state after restart; dormant control passed.
- The paired SV2 test mined compact shields at 10,671 and unshields at 10,672
  through the real pool with both the CPU binary and a physical Apple Metal
  GPU. That crosses mandatory witness-commitment enforcement as well as the
  selected compact/timing boundaries. Exact bytes, fees and commitments passed.

The paired tests exposed two daemon defects, fixed here without changing
validation rules:

- Block connection held the chainstate activation lock while waiting for the
  mempool lock; selection held the mempool lock while a pre-base coin callback
  requested chainstate. Admission and selection now acquire a lifetime guard
  in chainstate-before-mempool order. A unit regression failed before the fix;
  the real compact proof-failure recovery then mined and left the excluded
  transaction queryable in the mempool. Pre-base live-forest authorization and
  maturity checks are preserved. Contention/load qualification still applies.
- `generatetoaddress` omitted DNRW, failing at height 10,670. It now uses the
  same canonical witness-commitment builder as the other two assembly paths,
  before coinbase txid/Utreexo computation. The paired test crosses that exact
  boundary; the fast external-mining test independently checks the generated
  coinbase-only commitment. No witness rule or enforcement height changed.

The integration also includes #766's always-on tail-subsidy assertions. Its
prior Linux failure was the raw-assert meta-check: two assertions would have
disappeared under `NDEBUG`. They now explicitly fail Release builds on an
incorrect reward or a one-una overclaim; the assertion baseline is unchanged.

The lifecycle unshield retained the measured 42,053-byte encoding. These are
regtest compatibility results. Regtest skips chain PoW validation and cannot
establish real 60-second cadence, production hash-power adequacy or stale rates.

## Release gates still applying

Qualify the exact integrated Linux and ARM binaries, independent format/ASERT
review, sanitizer runs, production activation wiring, mixed-version/reorg and
snapshot/backfill behavior, mobile resource load, and real PoW network timing.
Pair source-pinned daemon, wallet, pool and worker artifacts in the release
manifest. CPU/GPU workers use the existing hash algorithm; job interruption,
target-only updates and actual backend execution require their own evidence.

Shared pool mining with compact transactions must compare DNRS, mandatory DNRW,
full DNRF, Utreexo roots, fees and payouts. Nonempty miner-owned solo/JD work needs
the separate negotiated commitment-context extension before it is advertised
as supported. Never infer that support from a shared-mode pass.

The owner has authorized release and earliest coordinated activation after all
gates pass. Outstanding qualification, rather than another permission request,
is the reason production remains unchanged.
