# v8.1.9 Vault and Contract Parity Evidence

Date: 2026-08-30

## Liquidity Vault

| Capability | dinero-qt | DineroDPI iOS | DineroDPI Android |
|---|---|---|---|
| Service/account metrics | NodeCore RPC | Embedded NodeCore RPC | Embedded NodeCore RPC |
| Operator mutation | Node operator UI | Not automatic | Not automatic |
| Withdrawal review | Required | Required | Required |
| Wallet/device authorization | Wallet unlock | Wallet PIN/biometric | Wallet PIN/biometric |
| Durable single-flight | QSettings journal | Wallet-scoped journal | SharedPreferences journal |
| Ambiguous response | Retry locked | Retry locked | Retry locked |
| Shared RPC fund movement | N/A | Disabled | N/A |
| Automatic queue processing | Node policy | Not triggered by mobile | Not triggered by mobile |

The mobile apps treat the embedded daemon as the vault authority. They do not
silently replace it with an app-local ledger and do not bind a node operator
identity automatically.

## Contracts and Covenants

Core/Qt remains the implementation authority. Both mobile apps expose the
Embedded NodeCore `contract.list` registry read-only. Mobile release/refund is
intentionally locked because the v8.1.9 context-aware `contract.getsighash`
handler reports that wallet signing is unavailable.

The Qt Release/Refund shortcut no longer sends placeholder signatures.
Broadcast remains limited to reviewed imported signature packages. A complete
wallet-generated signing package and idempotent broadcast contract are required
before enabling mobile contract fund movement.
