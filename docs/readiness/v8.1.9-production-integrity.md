# v8.1.9 Production Integrity Gate

Date: 2026-08-30

This document records the local production-integrity review performed while
hosted CI was unavailable. It is a release gate, not an activation approval.

## Ten-point result

1. **Placeholder and bypass inventory — closed.** The source scanner rejects
   dummy cryptographic material and production signing fallbacks. The unfinished
   standalone Lightning daemon is rejected in release configurations.
2. **Unsafe fallback removal — closed.** Qt contract release/refund signing and
   broadcast controls fail closed until a complete wallet signing implementation
   exists. Mobile contract actions remain read-only and locked.
3. **Bound signing package — implemented.** Contract signing-package identity
   commits to contract/action, funding outpoint, destination script, amount,
   chain, expiry, unsigned transaction, and signature hash.
4. **Negative signing tests — passed.** Tests reject modified package identity,
   contract/action/outpoint/destination/amount/chain, expiry, malformed fields,
   and replay.
5. **Authorization and single-flight — enforced.** Shielded transfer and vault
   withdrawal flows require review/authorization, persist the submitting state,
   and block automatic retries after ambiguous outcomes. Shared-RPC mobile fund
   movement stays disabled.
6. **RPC exposure — gated.** Fifty-nine canonical mutating RPC methods and fifty-one
   generated flat aliases inherit admin policy. Signature-debug and undo-debug
   methods require explicit development mode.
7. **Release capability inventory — generated locally.**
   `scripts/ci/check_rpc_admin_policy.py` emits the machine-readable RPC policy
   under `build/readiness/`; the full local campaign records provenance and
   hashes its evidence.
8. **Restart and duplicate-submit behavior — covered.** Shielded restart/reorg
   equivalence tests, vault submitting-state recovery tests, and shielded
   single-flight/recovery tests fail closed rather than blindly resubmitting.
9. **Physical-device safety — non-spending checks only.** Signed iOS install and
   launch and Android install/restart are supported by the local campaign.
   Funded-note proof execution and camera transfer remain explicit physical
   gates and must not be inferred from a build pass.
10. **Final independent pass — required before release.** Run the full campaign
    on the exact clean release commit, retain its evidence, then obtain review
    by a person who did not author these changes. Local self-review cannot be
    represented as independent external review.

## Mandatory local command

```sh
SHIELDED_FUZZ_SECONDS=300 ./scripts/shielded-full-local-campaign.sh
```

The campaign now begins with the RPC-policy and production-placeholder checks.
Any phase failure produces a nonzero final result while preserving the logs.

## Explicit release locks

- Do not enable mainnet shielded spend authority without an approved height,
  pool policy, activation preflight, and independent review.
- Do not enable contract release/refund until the daemon can construct and
  validate the bound package end to end and sign the actual funding output.
- Do not ship the standalone Lightning daemon while mock oracles, placeholder
  identity material, or incomplete reorg/justice handling remain.
- Do not treat simulator, unit-test, or install evidence as proof that a funded
  transaction path succeeded on a physical device.
