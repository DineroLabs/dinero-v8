### Issue 4: P2P Connection Retry Flood

**Severity**: 🟢 MINOR (Expected behavior, cosmetic)

**Symptoms**:
- 300+ "Failed to connect to 127.0.0.1:21001" messages in stderr
- Messages repeat continuously
- Fills logs with noise

**Example Output**:
```
[2025-12-15 10:33:07.123] [ERROR] Failed to connect to 127.0.0.1:21001: Connection refused
[2025-12-15 10:33:07.156] [ERROR] Failed to connect to 127.0.0.1:21001: Connection refused
[2025-12-15 10:33:07.189] [ERROR] Failed to connect to 127.0.0.1:21001: Connection refused
... (repeats hundreds of times)
```

**Root Cause**:
- Regtest has seed nodes configured (127.0.0.1:21001)
- No actual seed node running
- P2P layer aggressively retries connection
- This is expected in regtest mode (no peers exist)

**Why This Isn't Critical**:
- Regtest operates in single-node mode
- P2P failures don't affect RPC functionality
- Mining and consensus work without peers

**Potential Improvements**:
1. **Reduce Retry Rate**: Make P2P retry exponential backoff
2. **Suppress Regtest P2P Errors**: Log at DEBUG level instead of ERROR
3. **Disable Seed Nodes in Regtest**: Don't attempt seed connections in regtest

**Code Location** (likely):
```cpp
// src/network/p2p_manager.cpp or similar
if (network == "regtest") {
    // Don't attempt seed node connections
    return;
}
```

**Priority**: Low - cosmetic issue, doesn't affect functionality

## Root Cause - CONFIRMED

### ✅ Root Cause Identified: Two Critical RPC Client Issues

**Investigation Date**: 2025-12-15 12:00-12:30

#### Issue 1: Missing -datadir Parameter

**Problem**:
- Daemon started with: `-datadir="$DATA_DIR"` (custom temp directory)
- Daemon creates cookie at: `$DATA_DIR/.cookie`
- RPC client called without `-datadir` parameter
- RPC client looks for cookie in default location: `~/.dinero/.cookie`
- **Cookie not found → Authentication fails → RPC client hangs/times out**

#### Issue 2: Invalid -regtest Flag

**Problem**:
- Test script used: `$CLI -regtest -rpcport=$RPC_PORT`
- `dinero-cli` **does not support `-regtest` flag**
- Valid CLI options: `-datadir`, `-rpcport`, `-rpchost`, `-rpcuser`, `-rpcpassword`
- **Result**: "Unknown option: -regtest" error, RPC client exits immediately

**Evidence**:
1. ✅ Binaries verified to exist and be executable:
   ```
   -rwxr-xr-x  1 haydarevich  staff   293K Dec 15 04:23 ./dinero-cli
   -rwxr-xr-x  1 haydarevich  staff    17M Dec 15 04:25 ./dinerod
   ```
2. ✅ Daemon created cookie at: `/tmp/dinero-e2e-test-$$/regtest/.cookie`
3. ❌ RPC client looking in: `~/.dinero/regtest/.cookie` (wrong location!)
4. ✅ Manual test confirmed: `dinero-cli -regtest ...` returns "Unknown option: -regtest"

**Original Code** (line 58-60):
```bash
rpc() {
    $CLI -regtest -rpcport=$RPC_PORT "$@" 2>&1
}
```

**Fixed Code**:
```bash
rpc() {
    $CLI -datadir="$DATA_DIR" -rpcport=$RPC_PORT "$@" 2>&1
}
```

**Changes Applied**:
1. ✅ Removed invalid `-regtest` flag
2. ✅ Added missing `-datadir="$DATA_DIR"` parameter

**Commit**: `2861ed7a` - fix: Correct RPC client parameters in integration test

**Status**: PARTIAL FIX - Test still hanging after fixes applied
**Next Steps**: Further investigation needed - RPC client may have additional issues

2. **Add error handling to test scripts**
   ```bash

       local result
       result=$($CLI -regtest -rpcport=$RPC_PORT "$@" 2>&1) || {
           log_fail "RPC command failed: $*"
           return 1
       }
       echo "$result"
   }
   ```

3. **Add timeouts to prevent hangs**
   ```bash
   timeout 10s ./dinero-cli -regtest -rpcport=18443 blockchain.getinfo
   ```
