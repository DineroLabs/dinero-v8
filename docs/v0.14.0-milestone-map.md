## Architecture Constraints

### What v0.14.0 Does

**Block Template Construction**:
- Select transactions from mempool
- Respect block weight limit
- Honor ancestor/descendant rules
- Apply package feerate (CPFP)
- Deterministic ordering (tie-breaks)

**Fee-Optimal Selection**:
- Sort by ancestor feerate (not individual feerate)
- Handle CPFP naturally
- Never violate package limits
- Maximize block revenue (not tx count)

**Mining RPC Interface**:
- `getblocktemplate` - Returns block template
- `submitblock` - Validates and accepts block
- Integration with mempool (remove confirmed txs)
- Integration with fee estimator (record confirmations)

**Proof Layer**:
- Integration test: full mining lifecycle
- Wallet → mempool → mined → confirmed
- Restart after mining works cleanly

### What v0.14.0 Does NOT Do

🚫 **Out of Scope**:
- Fancy mining heuristics
- ML fee prediction
- Wallet/mempool interface changes
- Block relay optimizations (BIP152)
- Stratum protocol changes
- GPU mining changes
- Mining pool features

These are polish/optimization work, not architecture.

### v0.14.0.3 — Mining RPC Interface

**Goal**: Expose mining in a real, usable way

**RPCs**:

**`getblocktemplate`**:
- Input: None (uses current mempool state)
- Output: Block template (JSON)
  - `version`, `previousblockhash`, `transactions[]`, `coinbasevalue`, `target`, `mintime`, `curtime`, `height`
- Behavior: Template reflects current mempool state

**`submitblock`**:
- Input: Block hex
- Output: Success or rejection reason
- Behavior:
  - Validates block
  - If valid: accept, clear mempool entries, record confirmations
  - If invalid: reject with reason

**Integration**:
- Accepted block clears mempool entries
- Fee estimator records confirmations
- ChainDB stores new block

**Exit Criteria**:
- ✅ Wallet → mempool → mined → confirmed works
- ✅ Fee estimator sees confirmations
- ✅ No stale mempool entries after block acceptance
- ✅ `getblocktemplate` returns valid template
- ✅ `submitblock` validates correctly

**Files Expected**:
- `src/rpc/methods_mining.cpp` (new or modified)
- `include/mining/block_assembler.h` (modified - RPC integration)

**Pattern**: Interface layer - expose foundation to users

### v0.14.0.4 — Mining Integration Test (PROOF)

**Goal**: Prove the full mining lifecycle works end-to-end

**Test Flow** (MANDATORY):
1. Start node (regtest)
2. Create wallet
3. Mine 110 blocks (for spendable funds)
4. Create transactions (varying feerates)
5. Assert transactions in mempool
6. Call `getblocktemplate`
7. Assert template includes high-fee transactions
8. Mine block (using template)
9. Call `submitblock`
10. Assert block accepted
11. Assert transactions removed from mempool
12. Assert fee estimator recorded confirmations
13. Assert fees credited to wallet
14. Restart node
15. Assert state clean (no duplicate txs)

**Exit Criteria**:
- ✅ Full lifecycle works (wallet → mempool → mining → confirmation)
- ✅ Restart after mining is clean
- ✅ No double-spends
- ✅ CPFP packages mined correctly
- ✅ Fee estimator tracks confirmations
- ✅ Mempool persistence doesn't reload confirmed txs

**Files Expected**:
- `tests/integration/test_mining_lifecycle.sh` (new)

**Pattern**: Proof layer - nothing is "done" until it survives a restart

## Design Principles

**Determinism**:
- Same mempool state → same block template
- Tie-breaks must be reproducible
- No randomness in selection

**Fee Optimization**:
- Maximize revenue (not tx count)
- Respect ancestor feerate (CPFP)
- Never violate consensus rules

**Integration**:
- Mempool clears confirmed txs
- Fee estimator tracks confirmations
- Persistence doesn't reload confirmed txs

**Proof-First**:
- Nothing is "done" until integration test passes
- Restart behavior must be correct
- Full lifecycle must work
