coinbase output matching the post-block SHR1 digest. Supported internal and
external mining interfaces construct the commitment through the shared assembler.
External miners must preserve the daemon-owned coinbase and transaction set.

A snapshot whose base is at or after 111000 must be v5, prove its coinbase against
the selected PoW header's transaction Merkle root, match the full shielded state

base at 111000 first satisfies it at selected header height 111288. This is a
local risk policy, not guaranteed finality. Older snapshot bases retain their
historical acceptance rules and cannot claim this new authentication property.

## Deterministic v5 export timestamp

New v5 exports record the base block timestamp in the container header. The
publisher's wall-clock `generated_at` belongs in the external manifest. This
removes export time as a source of different file hashes at the same base.
Legacy v4 exports retain creation-time semantics. Readers continue accepting
previous v5 files with creation-time timestamps; this is an exporter change,
not a new consensus rule or a retroactive change to published snapshots.

The mandatory binding test compares repeated full v5 exports and exports from
an independent node that validates the same blocks, checks the timestamp against
the base block, preserves v4 behavior, and loads an older-style v5 timestamp.
This is bounded fixture evidence, not a guarantee across all exporter versions.
Discovery must still require matching full-file hash and size before resuming
bytes across providers; matching base hash alone is insufficient.

### Export ordering audit

- UTXO records: copied outpoints are explicitly sorted before canonical record
  encoding; the unordered-map traversal does not define output order.
- Utreexo forest: roots and nodes serialize in indexed vector order; deleted
  positions are copied from the unordered set and explicitly sorted.
- Commitment frontier: size plus a fixed depth-indexed array, with every output
  byte populated. This is ordered tree state, not unordered iteration.
- Anchors: serialized from the chronological deque. Its order is meaningful
  state and must not be sorted by root hash.
- Nullifiers: SQLite query explicitly orders by block height and nullifier bytes;
  physical insertion/row order does not select the serialized order.
- Metadata, Utreexo and shielded-section reserved fields initialize to zero.
  Serialization writes fields individually, not padded C++ structs. No new
  reader rejection rule is introduced for existing reserved/timestamp values.

A second real-node fixture includes shielded deposits and two distinct spent
nullifiers, then compares an uninterrupted exporter with an independently synced
node after disconnect/reconnect through the shielded activity and restart.
Cross-architecture and all-version equivalence remain separate evidence; provider
selection must never infer byte identity merely from the same base hash.

### Anchor-window completeness

Do not require exactly `AnchorHistory::kDepth` entries before publication. A
base shortly after genesis or an epoch reset legitimately commits a shorter
window. The v5 load gate verifies the exact serialized anchor history through
SHR1 and DNRS; removing an entry at that same base is a commitment mismatch,
not another valid representation of its state. Snapshot loading restores the
serialized anchors, rather than starting a new empty window. `kDepth` affects
both spend validity and the committed digest and requires a consensus transition
to change.

The binding fixture exports at reset height 10 plus two blocks, checks that
three anchors are retained, and loads the buried snapshot under enforcement.
It also removes one anchor, repairs the section length and file checksum, and
requires commitment-mismatch rejection without imported or persisted state.
