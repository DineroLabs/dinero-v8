v0.13.0 completes the **Network Layer** by enabling real transaction relay, mempool persistence across restarts, and fee estimation for wallet optimization.

**Why This Matters**: Without transaction relay, nodes cannot share new transactions. Without mempool persistence, restarts lose pending transactions. Without fee estimation, wallets cannot optimize fees.

1. First, get basic relay working (v0.13.0.1)
2. Then, add persistence (v0.13.0.2)

# Milestone 13.1: Transaction Relay

**Theme**: Enable real transaction propagation between nodes
**Blocker**: 🚨 YES – Required for multi-node operation
**Estimated Complexity**: Moderate

---

## What 13.1 IS

Complete implementation of transaction relay:
1. **Transaction Deserialization** – Parse wire format (vector<uint8_t>) into Transaction object
2. **Network Handler Fix** – Replace dummy transaction creation with real deserialization
3. **Mempool Integration** – Route received transactions through mempool validation
4. **Relay Logic** – Announce valid transactions to other peers (via inv messages)
5. **Duplicate Detection** – Don't relay transactions we already have

**Core Principle**: Relay is NOT broadcasting. A node receives tx from peer A, validates it, then announces (inv) to peers B, C, D. Those peers request (getdata) if interested.

---

## What 13.1 IS NOT

- ❌ **NOT implementing bloom filters** (BIP37) – Naive relay to all peers is acceptable
- ❌ **NOT implementing trickle relay** (privacy batching) – Immediate announcements are fine
- ❌ **NOT implementing fee-based relay policy** – Accept all valid transactions
- ❌ **NOT implementing compact block relay** (BIP152) – Full transactions only
- ❌ **NOT implementing transaction request management** – Basic getdata handling only

**Rationale**: These are optimizations. Basic relay must work first.

bool NetworkManager::handleTxMessage(std::shared_ptr<PeerConnection> peer, const P2PMessage& message) {
    const auto& tx_msg = static_cast<const TxMessage&>(message);

    g_logger.info("Received transaction from peer " + peer->getPeerId());
    m_stats.transactions_received++;

    if (!m_mempool) {
        g_logger.warning("No mempool available");
        return false;
    }

    // 1. Deserialize transaction
    auto tx_opt = Transaction::TryDeserialize(tx_msg.tx_data);
    if (!tx_opt) {
        g_logger.warning("Failed to deserialize transaction from peer " + peer->getPeerId());
        peer->adjustScore(-5);  // Penalize for sending malformed data
        return false;
    }

    const Transaction& tx = *tx_opt;
    std::string txid = tx.GetTxid();

    // 2. Check if we already have it
    if (m_mempool->hasTransaction(txid)) {
        g_logger.debug("Transaction already in mempool: " + txid);
        return true;  // Not an error
    }

    // 3. Add to mempool (validates and stores)
    if (m_mempool->addTransaction(tx, false)) {  // false = don't relay yet
        g_logger.info("Added transaction to mempool: " + txid);
        peer->adjustScore(+2);  // Reward for valid transaction

        // 4. Relay to other peers (excluding sender)
        relayTransactionToOtherPeers(tx, peer->getPeerId());

        return true;
    } else {
        g_logger.warning("Mempool rejected transaction: " + txid);
        peer->adjustScore(-3);  // Penalize for invalid transaction
        return false;
    }
}
```

**Validation Flow**:
```
Wire bytes → Deserialize → Mempool validation → Relay to others
```

void NetworkManager::relayTransactionToOtherPeers(const Transaction& tx, const std::string& exclude_peer_id) {
    // Create inventory announcement
    InvMessage inv_msg;
    InventoryVector inv_item(InventoryType::MSG_TX, tx.GetTxid());
    inv_msg.inventory.push_back(inv_item);

    // Send to all peers except sender
    std::lock_guard<std::mutex> lock(m_peers_mutex);
    for (auto& peer_pair : m_peers) {
        if (peer_pair.first == exclude_peer_id) continue;  // Skip sender

        if (peer_pair.second->isHandshakeComplete()) {
            peer_pair.second->sendMessage(inv_msg);
        }
    }
}

# Milestone 13.2: Mempool Persistence

**Theme**: Survive restarts without losing pending transactions
**Blocker**: ⚠️ NO – Nodes can rebuild mempool from network
**Estimated Complexity**: Low

---

## What 13.2 IS

Mempool state persistence across daemon restarts:
1. **Save Mempool on Shutdown** – Serialize all mempool transactions to disk
2. **Load Mempool on Startup** – Deserialize and validate transactions against current chain
3. **Prune Stale Transactions** – Remove transactions that are now invalid (spent inputs, conflicts)
4. **RPC Integration** – Add `savemempool` and `loadmempool` RPC commands (optional)

**Core Principle**: Mempool is ephemeral but can be checkpointed. After restart, mempool should contain all valid pending transactions.

---

## What 13.2 IS NOT

- ❌ **NOT saving mempool metadata** (arrival times, peer info) – Just transactions
- ❌ **NOT guaranteeing transaction order** – Mempool rebuilds priority from scratch
- ❌ **NOT checkpointing during operation** – Only on shutdown/explicit save
- ❌ **NOT syncing mempool across nodes** – Each node has independent mempool state

**Rationale**: Persistence is for UX (don't lose pending txs on restart), not consensus.

---

bool Mempool::loadFromDisk(const std::string& filepath) {
    // 1. Parse JSON
    auto mempool_data = parseJSON(filepath);
    if (!mempool_data) return false;

    // 2. Validate version
    if (mempool_data["version"] != 1) {
        g_logger.error("Unsupported mempool version");
        return false;
    }

    // 3. Load transactions one by one
    size_t loaded = 0;
    size_t rejected = 0;

    for (const auto& tx_json : mempool_data["transactions"]) {
        std::string tx_hex = tx_json["hex"];
        std::vector<uint8_t> tx_data = hexToBytes(tx_hex);

        auto tx_opt = Transaction::TryDeserialize(tx_data);
        if (!tx_opt) {
            rejected++;
            continue;
        }

        // Validate against current chain state
        std::string error;
        if (addTransaction(*tx_opt, false)) {  // Don't relay on load
            loaded++;
        } else {
            rejected++;
            g_logger.debug("Rejected persisted transaction: " + tx_opt->GetTxid());
        }
    }

    g_logger.info("Loaded " + std::to_string(loaded) + " transactions, rejected " + std::to_string(rejected));
    return true;
}
```

**Why Validate**: Chain may have progressed during downtime. Transactions may now be:
- Confirmed (inputs spent in a block)
- Conflicting (double-spent by another transaction)
- Invalid (low fee rejected by new policy)

# Milestone 13.3: Fee Estimation

**Theme**: Help wallets choose optimal fees
**Blocker**: ⚠️ NO – Wallets can use fixed fees
**Estimated Complexity**: Moderate

---

## What 13.3 IS

Economic fee estimation based on mempool and block confirmation data:
1. **Track Transaction Arrival** – Record when transactions enter mempool
2. **Track Confirmation Times** – Record which block confirms each transaction
3. **Maintain Fee Buckets** – Group transactions by fee rate (low/medium/high)
4. **Provide Estimates** – RPC `estimatefee <target_blocks>` returns recommended fee rate
5. **Wallet Integration** – WalletMempoolAdapter uses fee estimates for coin selection

**Core Principle**: Fee estimation is NOT exact. It's a statistical prediction based on recent history.

---

## What 13.3 IS NOT

- ❌ **NOT implementing smart fee (Bitcoin Core algorithm)** – Simple bucket-based approach
- ❌ **NOT guaranteeing confirmation** – Estimates are probabilistic, not guaranteed
- ❌ **NOT tracking replace-by-fee** (RBF) – Assume static fees
- ❌ **NOT optimizing for privacy** – No consideration of address reuse, etc.

**Rationale**: Simple fee estimation works for 90% of use cases. Advanced algorithms can come later.

---
